## 改了什么

**收起那行**：提示从「写一句目标，拆成步骤和每步要做的事」换成「如果不知道该怎么做，不如让AI帮你拆解任务」。原来那句是在教操作，这句是在说它能帮上什么忙——收起态本来就只占一行，说清价值比说清步骤有用。

**输入区沿用小任务窗口的样式**：不再是一个大按钮「拆成步骤」，改成一行三段，高度都是 38：

| 位置 | 内容 | 与面板一致的地方 |
| --- | --- | --- |
| 左 | 38×38 白底描边方键，回形针图标 | 与面板「更多」键同高同描边 |
| 中 | 输入框，圆角 8、线二档描边，最多长到 104 再框内滚动 | 与面板输入框同高同圆角同占位字色 |
| 右 | 42×38 白底描边发送键，拆的时候换成 16 号转圈 | 与面板发送键同尺寸同底色 |

两处的「问一句」看起来是一件东西，人才会在卡住时都用它，而不是记住「这里是一种、那里是另一种」。

## 图片与文件怎么进模型

| 环节 | 做法 |
| --- | --- |
| 挑 | `AttachmentPicker` 端口（`domain/port/attachment_picker.dart`）；Windows 实现 `DesktopAttachmentPicker` 走 `file_picker`，系统文件框可多选 |
| 图 | 按后缀认（png/jpg/jpeg/webp/gif/bmp），读字节编 base64，单张 ≤ 4MB |
| 文本 | 按后缀认（txt/md/json/yaml/csv/log/html/xml 与常见代码后缀），UTF-8 读、坏字节换替换符，正文 ≤ 8000 字并留一句「后面还有」 |
| 其他 | 直接跳过，把原因攒起来一起说，不整批作废 |
| 上限 | 一次 5 个（`AiAttachment.maxCount`），满了附件键置灰 |
| 发送 | `ChatClient` 没附件时仍发纯字符串；有附件才换成数组：文字一段、每张图一段 `image_url`（`data:` + base64）、每份文本并进文字段并标出文件名 |
| 空话 | 只带附件不写字也能发，话术里写「（没有文字说明，按附件内容判断）」 |

几处判断：

- **文本文件不单独占一段**。模型读 `content` 数组时，多个 text 段与一段长文本对它的区别很小，但抓包看请求时一段更好读，也省一层拼接。
- **只认后缀不猜内容**。把 PDF、docx 的字节当 UTF-8 读进来只会是乱码，乱码进上下文比拒掉更糟；认不出就说「这类文件读不了，换成图片或文本文件」。
- **跳过的文件不整批作废**。拖五个进来，其中一个 8MB 的图，收下四个再补一句，比全拒了让人重挑一遍好。
- **挑文件失败不进 `failed` 那态**。那是「模型没拆出来」的位置，挑文件没成只该影响输入区的灰字，不能顺手把上一次拆好的步骤清掉。

## 实机

重启应用后：进任一项目详情 → 展开「AI 帮助」→ 点左边的回形针，选一张图（或一份 md）→ 输入框下方出现文件名标签，点叉能移掉 → 不写字直接点发送，等回话与步骤出来 → 点「应用到项目」。

注意模型这头：默认的 `deepseek-chat` 是纯文本模型，图片段发过去会被它拒或在服务端被忽略，这时卡片里会出现一句失败原因，页面不崩。要让图片真的起作用，把 `app/providers.dart` 里 `HttpChatClient` 的 baseUrl 与模型名换成支持视觉的一家——同一套 OpenAI 兼容协议，只改这一处，端口与页面都不动。设置页目前还没有开放模型名这一项，B24 再补。
