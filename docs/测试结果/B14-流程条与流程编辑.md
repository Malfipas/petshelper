## 改了哪些

- 数据层补单条步骤读写：`StepsDao` 加 `byId` / `insertOne` / `updateRow`；`TaskItemsDao` 加 `clearStep`；`ProgressEntriesDao` 加 `shiftAfter`。新增行与替换整表并存，不改老调用点。
- `ProjectRepository` 新增 `renameStep`、`addStep`、`moveStep`、`deleteStep`。`ProjectRepository` 多持一个 `_db` 只为了把跨表写握进一个事务。
- `addStep` 的编号取现有最大值加一，不取行数：删过中间一步后行数会比最大编号小，按行数会撞号。
- `deleteStep` 单事务里做五件事：该步待办 `stepId` 置空、删步骤行、后续编号各前移一位、进度史里编号大于被删位置的前移一位、`currentStep` 收敛（大于被删位置减一、越界收到末位、删光回 -1）。
- 进度史里指向被删那一步的记录保持原编号，只把后面的前移：那条史记的是当时的位置，猜它该并到哪一步不如让它自己容错。
- `ProjectListState` 加 `detailSteps` / `filterStep` / `flowEditing`，`copyWith` 补 `clearFilter` 并在 `clearDetail` 时一并清掉；`detailDoneSteps` / `detailPercent` 继续由 `detailSteps` 推出。
- `moveStep` 换的是「位置」：两步的 `index`、各自待办的 `stepId`、进度史里两条 `stepIndex` 一起换，与 requirements FR-08 一致；到头返回 `false`，界面不写库也不清筛选。
- 写操作一律「先落库、再读回 bundle 重算」，界面不做乐观更新。改名的输入框失焦或回车提交，`trim` 后为空就不动。
- 进详情默认筛 `filterFor(currentStep)`：`stepCount <= 0` 不筛，`currentStep < 0` 取 0，越界收末位。
- `collapse()` 加了编辑器一层：`confirming` → `flowEditing` → `openId`，三步都不命中才交给壳收窗口。
- 页面相对日期改读 `ProjectListNotifier.now`（注入时钟），页面测试把时钟固定到 `2026-10-24`，跨天跑也不会把「今天」翻成「昨天」。

## 偏差

| 项 | 原型 / PRD | 实现 | 为什么 |
| --- | --- | --- | --- |
| 已完成段判定 | 原型按「前 cur 段」着色 | 按每步自己的 `state` | 完成状态允许不连续，按步态才不会把没做的段刷成完成 |
| 编辑行第四枚小键 | 原型有「＋ 事」 | 本块只放 ↑ ↓ 删除 | 那颗键要开行内输入并写待办，归 B15 |
| 删步骤后的 `currentStep` | 原型 `cur` 不调整 | 大于被删位置减一、越界收末位、空则 -1 | 原型 `cur` 是「已完成步数」，我们的 `currentStep` 是「正在推进的下标」 |
| 虚线边 | 原型 `1px dashed` | 自绘 4/3 节奏虚线 | Flutter 无现成虚线边，`line2` 在原型里未定义，沿用 B13 的取色 |
| 加一步的默认名 | PRD 写「新步骤」 | 「新步骤 N」（N 为追加后的步数） | 连加几步时同名，编辑器里分不出哪行是哪行 |
