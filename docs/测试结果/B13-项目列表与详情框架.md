## 改了哪些

- 页面整页新建：B05/B11 时这里是 `ComingSoon` 占位，`page-projects` 键留在最外层 `KeyedSubtree` 上，壳认页的逻辑没动。
- 路由改成能带 query：`router.dart` 的 `_pageOf(tab, projectId)` 把 `state.uri.queryParameters['id']` 交给 `ProjectsPage`，面板「查看」与截止气泡可以直落某个项目。
- `?id=` 的展开走 `initState` + `didUpdateWidget` 两处：路由只换 query 时页面 State 被复用，`initState` 不会再跑，只写 `initState` 会出现「从列表点第二个项目地址变了、详情还停在旧的那个」。
- 展开放在 `postFrame` 里跑：第一帧列表还没读回来，直接 `open` 会让详情里的「最近推进」取不到行数据。
- Esc 顺序改成三层：`main_shell.dart` 里在「收详情」之前先问删除弹窗，`collapse()` 返回 `true` 表示这一下被页面吃掉。
- 重名判定走 Repository 现有数据逐条比对，不建唯一索引：名称允许改、允许重名历史数据，唯一约束会把老库卡住。
- 字体在主题层统一成 `Microsoft YaHei UI`（`AppTheme.fontFamily`），中文数字与标点在详情进度行里才不歪。
- 代码审查中按「单文件 ≤ 500 行」拆了一次：`projects_page.dart` 首版 541 行（页头、表单、列表、空态、弹窗、按钮全挤在一个文件里，`_buildForm` 也过百行），拆出 `project_widgets.dart`（页头与按钮）、`project_form.dart`（新建表单自管两个控制器）、`project_confirm.dart`（删除弹窗），页面本体落到 181 行，键与数值一个没动，拆分后重跑 23 条与全量 309 条全过。

## 偏差

| 项 | 原型 / PRD | 实现 | 为什么 |
| --- | --- | --- | --- |
| 截止日期选择 | 原型给一行日期框 | 点开 `showDatePicker`，空值显示「不设截止」 | 桌面端自绘日历成本高，系统选择器行为一致 |
| 删除后的提示 | 原型打事件台 | 页头右侧一行灰字，`takeFlash` 取走即清 | 事件台是演示控制台，不是产品部件 |
| 建完自动展开 | PRD 写「回到列表」 | 建完直接进该项目空详情 | 建完的空项目没有待办，停在列表只剩一张空卡片，进详情才有下一步入口（详情内容 B14 接） |
| 详情滚动 | 整页 `overflow:auto` | 页头固定，只滚详情区 | B11 已定：壳不提供整页滚动 |
| 「最近推进」取数 | 原型存 `updatedAt` | 取该项目已完成步骤的最大推进时间，没有则退回创建时间 | 进度史与步骤状态是唯一事实来源，另存时间戳会分叉 |

## 顺延

- 流程分段条、步骤编辑归 B14；本项目待办卡片与「从独立事项移入」归 B15；进度史与时间轴归 B16；详情里的 AI 帮助块归 B22/B23。
- 实机手动项：新建键与卡片 140ms 悬停换色的观感、日期选择器在 1 倍与 2 倍屏下的落位、`?id=` 从面板「查看」真实跳转的连贯性，与 B06–B12 的窗口项合并到 Windows 上点一轮。
