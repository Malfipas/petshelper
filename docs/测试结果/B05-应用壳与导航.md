## 排错记录

**`StartTask` / `StopTask` 构造是位置参数。** providers 里先按命名参数写，analyze 报 `no named parameter`。看清楚 B04 的实现：这两个用例只有一个端口，写成位置参数；`FinishTask`、`MoveTask`、`ClassifyIdea`、`SummarizeDay` 有两个以上端口，用命名参数。改回位置参数后消除。

**drift 生成的 `Idea` 与领域实体同名。** `providers.dart` 要 `AppDb` 类型，一 import 就把 drift 的 `Idea`、`Note` 行类也带进来，与 `domain/model/` 的同名实体撞车。用 `import '../data/db/app_db.dart' hide Idea, Note;` 只取数据库类型。

**riverpod 3 会把 provider 里抛的异常包一层。** 断言「没注入数据库时读取报错」时，`throwsA(isA<UnimplementedError>())` 不成立，实际收到的是 `ProviderException`，且这个类型不从 `flutter_riverpod` 导出（在 `src/` 里）。改为断言错误文案包含「appDbProvider 还没装配」，测的仍是「报错要告诉人怎么装」这件事。

**smoke_test 的 import 跟着挪。** `AiPetApp` 从 `main.dart` 移到 `app/app.dart`，B01 那条冒烟测试改 import 路径。断言的产品名没有变——`MainShell` 顶部仍显示「AI桌宠日常助手」，B11 按原型精修时再决定这一行去留。
