# B16 修正：主界面不许拖，只有桌宠能拖

使用者 2026-10-27 反馈「主界面的拖拽仍然问题很大」，要求改成**主界面不可拖拽、仅桌宠可拖拽**。总计 621 条通过、0 失败（上一轮 615 条，本轮净增 6 条）。

跑法：`cd app; flutter test`、`dart analyze lib test`（本机 `flutter analyze` 会崩，一律用 `dart analyze`）。

## 一、问题出在哪

上一轮给主界面单独加了一条 16 像素高的拖动条（`_ShellDragBar`），主界面与桌宠各自有一套拖动入口。实机上仍然别扭，原因有两层：

1. 主界面是居中浮在那儿的整块界面，拖起来没有「该停在哪」的直觉，松手也没有吸附，位置就全凭手；
2. 主界面档的桌宠拖动还是交给系统的。这一档窗口是「主界面 ∪ 宠物」的并集，系统拖的是**整个窗口**——一拖宠物，主界面就跟着一起平移，松手才被重新摆回居中，看上去像「跳一下」。

真正想要的是：**主界面钉死居中，只有桌宠能被拖，拖宠物时主界面一动不动。**

## 二、改了什么

| 位置 | 改动 |
| --- | --- |
| `app/main_shell.dart` | 撤掉 `_ShellDragBar` 整个 widget，顶部那 16 像素改成纯留白 `SizedBox(height: 16)`（键 `main-shell-top`）；`main-shell-drag` 不再存在 |
| `platform/window/pet_layout.dart` | `mainBounds` 去掉 `origin` 参数与 `mainMinVisibleTop` 常量，主界面恒居中；`petLayout` 新增 `petOverride`，拖动中的宠物框按它摆 |
| `platform/window/pet_window.dart` | 删掉 `beginMainDrag` / `dragMainBy` / `endMainDrag`；新增 `dragPetBy(delta)`；`beginDrag` 按档位分叉 |
| `features/pet/pet_stage_port.dart` | 端口换成 `beginDrag` / `dragBy` / `endDrag`，主界面那三个方法撤掉 |
| `features/pet/pet_on_main.dart`、`features/pet/pet_page.dart` | 拖动中逐帧把指针位移喂给窗口层，抬手显式收尾 |

### 拖动现在怎么走

| 档位 | 起手 | 跟手 | 松手 |
| --- | --- | --- | --- |
| 常驻（收起） | 交给系统 `startDragging` | 系统整窗跟手（窗口就是宠物） | 系统拖动反推位置，吸回右缘 |
| 主界面 | 窗口临时铺满工作区，记下宠物当前框 | 指针位移 → `dragPetBy`，宠物自己走 | 界面抬手调 `endDrag`，吸回右缘，窗口缩回并集 |
| 面板 | 不给拖 | — | — |

主界面档为什么非要自己算：窗口是「主界面 ∪ 宠物」的并集，交给系统就是搬整块，主界面必然跟着走。铺满工作区之后，宠物与主界面在屏幕上的位置各算各的，拖谁是谁。

拖动中的宠物至少留 48 像素在屏里（`PetWindow.petKeepVisible`），横向纵向都夹一道，拖出屏幕还抓得回来；松手横向一律回右缘，只记纵向比例，与常驻档同一套吸附。

## 四、实机核对

1. 主界面里按住顶部 16 像素那条空白拖：界面不动，指针变成普通箭头而不是抓手。
2. 进主界面后按住桌宠拖：只有桌宠跟着走，主界面那块纹丝不动（不再有「跟着飘一下再弹回来」）。
3. 松手：桌宠贴回桌面右缘，高度停在能吸到的那一档；主界面仍在正中。
4. 把桌宠往屏幕左下拖到很远再松手：至少还有 48 像素在屏里，抓得回来。
5. 常驻档（收起）拖桌宠：跟手依旧顺，松手吸边。

## 五、缺口

- `PetOnMain` 与 `PetPage` 里的宠物是两份实现，拖动喂位移的逻辑各写了一遍。目前两处都有用例盯着，但以后改拖动规则得记得改两处；B24 可以把这块收成一个小 widget。
- 主界面固定居中之后，`mainOrigin` 这条持久化线索彻底没了（原本也没写库），设置里若还留着相关字段属于历史残留，等下轮清理时一并看。
