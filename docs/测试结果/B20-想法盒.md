## 先校准的部分

B20 只做界面与页面状态。归类能力本身是 B04 落好的地基（`ClassifyIdea` 用例 + `IdeaClassifier` 端口），B20 只负责在「存下之后」调它一次。日总结、AI 总结正文仍是 B22/B23 的事，与这一页无关。

阅读 PRD 与原型后确定的口径：

1. **想法按收进来的时间倒序摆**，新建的进最上面（PRD 681）。
2. **每条只自动归一次**（PRD 673），之后再改标题、改正文都不再送 AI。
3. **没配 key 时归类停掉**，卡片标签写「未分类」；配了 key 只是还没轮到的写「待分类」（PRD 683）。
4. **用户手动搬分类说了算**：只要分类动过，就落归类时间，AI 不再覆盖（PRD 675）。
5. **删除两段式**：第一下按钮变红成「确认删除」，三秒没再点就还原（原型与 PRD 685）。
6. **分类改名只动分类自己**：想法存的是 `categoryId`，改名不用碰任何一条想法（PRD 674）。

## 实现

| 层次 | 内容 |
| --- | --- |
| 数据 | 没加表也没加列。`IdeaRepository` 已有的 `add`/`rename`/`setBody`/`markClassified`/`delete`/`ensureCategory`/`renameCategory` 够用 |
| 状态 | 新 `ideas_state.dart`：`IdeaBoxState`（想法、分类、看哪一类、编辑中、改名中、待确认删除、hasKey、nowMs）与纯函数 `ideaWhen` |
| 动作 | 新 `ideas_notifier.dart`：`refresh`、`selectCategory`、`startCreate`、`startEdit`、`saveNew`、`saveEdit`、`armDelete`、`delete`、`startRename`、`commitRename` |
| 界面 | `ideas_page.dart` 两栏（24 / 76，中间一条 `line` 竖线）；`category_column.dart` 左栏；`ideas_list.dart` 页头与列表；`idea_card.dart` 读卡、编辑卡、小按钮与标签 |
| 样式 | `theme.dart` 补三个令牌：`ideaTagBorder`、`hoverBg`、`cardHoverLine` |

几处判断：

- **标签的三种说法是有区别的**。「分类名」是真归好了，用主色；「待分类」是配了 key 但还没轮到，还会自动归；「未分类」是没配 key，不会再归。三者都从 `IdeaBoxState.tagOf` 出，界面不自己拼。
- **文案键用值而不是下标**。左栏每行的条数挂 `ideas-cat-count-<分类名>`，改名后跟着换；行本身用 `ideas-cat-<分类id>`，改名不影响选中。
- **编辑卡底部改成可换行**。下拉、没配 key 的提示、三个按钮原本挤一行，窄窗口会溢出；现在左组用 `Wrap`，放不下时提示自己掉到第二行。
- **进页刷一次**。页面 `initState` 里补一次 `refresh`，想法可能在别处被写进来。

## 与原型不一致的地方

都是照 PRD 走，或照已有的用例语义走：

1. **归不上时不标「已归类」**。原型把 `classified` 置真，之后不再试；`ClassifyIdea` 用例定的是「归不出结果就保持未分类」。后者更稳——模型临时抽风不该把一条想法永久钉在「待分类」上。界面上两种做法都显示「待分类」，看不出差别。
2. **新建时自己在下拉里选了分类，就算归好了**。原型在新建分支里忽略了下拉值，属于疏漏；用户亲手选的不该被丢掉。
3. **左栏底部那句「没配 API key…」没做**。PRD 683 只要求编辑态留一句，B19 验收时也刚把这类常驻提示并成一条页头提醒。现在只在编辑卡里出现一句「未配置 API key，AI 不再自动归类」。
4. **切分类会收起编辑态**。原型切走再切回来，编辑卡还在；收起更不容易误操作。
