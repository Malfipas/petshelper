## 排错记录

**`tray_manager` 0.8 把老 API 全标了弃用。** 网上示例几乎都是 `trayManager.setContextMenu(Menu(items: [MenuItem(key:)...]))` 加 `TrayListener`，在新版本里是 `@Deprecated`，用了会生成分析警告。改用 nativeapi 那套：`TrayIcon.create()`、`Menu.create()`、`MenuItem.createWithLabelAndType(label, MenuItemType.normal)`，点击监听挂在菜单项自己身上（`item.addListener`），不再有全局回调。

**`prefer_initializing_formals` 又拦了一次。** `LaunchAtStartupAutoStart({required String appName}) : _appName = appName` 被要求改成初始化形参，而命名参数不能以下划线开头。最后把字段改成公开 `final` 并用 `this.appName`，路径参数给默认值 `Platform.resolvedExecutable`——比原来的 `current()` 工厂更省一层。

**托盘图标不能用 exe 旁边的文件。** 一开始想把 ico 放在程序目录，但 `ImageAsset.fromAsset` 是把 `pubspec.yaml` 里的资源名拼到 `data/flutter_assets/` 下按文件读的（见其实现），只有打进包才在安装到任意路径后仍然有效。图标由 `assets/桌宠/常驻-240.png` 裁顶部方形缩到 32×32 生成，`flutter:` 段里声明 `assets/icons/`。

## 五个设计决定

**托盘菜单只放两项，另加左键单击唤出。** 托盘是「窗口找不到了」的落脚处，不是第二个主界面；放一堆功能等于把设置页搬到通知区。左键单击也唤出，是因为 Windows 上多数托盘程序都这样，只留菜单会让人觉得点了没反应。

**装不上托盘不算启动失败。** `TrayController.start()` 把 `install()` 的异常吃掉并返回 `false`：没有通知区的机器照样能用主界面，缺的只是一个入口。

**自启开关「改完回读」。** `setOn()` 返回的是 `enable/disable` 成功之后重新查到的状态。系统可能拒收（策略限制），也可能说写了却没落地，界面按真实状态回显才不会骗人。

**退出顺序：卸托盘 → 关库 → 销毁窗口。** 反过来的话，托盘还挂着时库已关闭，用户再点一次「唤出主界面」就会碰到已关闭的数据库。

**窗口与托盘都经接口注入。** `TrayDriver`、`AutoStart` 都是窄接口，真实现各一个文件，provider 里装配；测试注入假实现。这条让「点菜单做什么」能在 CI 里跑——真图标与注册表留给手动清单。

## 已知未覆盖

- **单实例没做。** 双击两次图标会起两个进程、两个托盘图标。06 设计里要求单实例，但不在 B07 的判定里，留到 B24 打磨（可用命名互斥量或本地回环端口）。
- **自启只写 Windows 的 HKCU。** `launch_at_startup` 在 macOS/Linux 另有实现，本项目只发 Windows，不做跨平台兜底。
