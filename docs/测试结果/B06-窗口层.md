## 排错记录

**`prefer_initializing_formals` 连着拦了两次。** 先写 `required WindowDriver driver` 再在初始化列表里赋给 `_driver`，lint 要求写成 `this._driver`。改成位置参数 `this._driver` 之后，`edge`→`_edge` 的赋值仍被同一条规则拦。最终把两个命名参数改名为 `initialEdge`、`initialAnchorY`：名字不再与被赋字段同义，lint 不再报，语义上也更准——它们是初值，之后会被拖动改掉。

**假 driver 抽出去共用时踩了改名顺序。** 两个测试文件都要用同一个假窗口，抽到 `test/support/fake_window_driver.dart`。直接在旧文件里全局改 `_FakeDriver` → `FakeWindowDriver`，会把类定义本身也改名，与 import 进来的类重名。正确顺序是先删类定义、再改名调用处。

**测试里 `dart:ui` 是多余 import。** `flutter_test` 已经导出 `Offset`、`Rect`，`analyze` 报 `unnecessary_import`，删掉即可。

## 三个设计决定

**只有主键起手，判定在 `canStartDrag`。** 用 `buttons & 0x01` 而不是等值比较：左键与别的键一起按着时手指没抬起来，仍该跟着走；右键、中键、两键同按都不算。界面层在指针按下时判过再叫 `beginDrag()`，窗口层不重复判。

**中心正好压在中线上算没越线。** `settlePlacement` 用 `<=` 判左，否则手一抖停在中线上就在两侧之间来回跳。

**窗口层不认识设置表。** `PetWindow` 只认 `WindowEdge` 与 0 到 1 的纵向比例，落位变化通过回调交出去；`PetSide` 与 `WindowEdge` 的对照、以及写进 settings 的两行，都放在 `app/pet_window_launcher.dart`。这样 `platform/` 不 import `data/` 也不 import `domain/`，换平台只动这一层。
