# B17 修正：项目事项完成后「推进项目数」仍为 0

实机反馈：项目事项完成后被计入完成件数，但右栏「推进 N 个项目」一直是 0。

## 一、现象与根因

查真实库 `D:\我的文档\app.db`（临时 Python 只读，查完即删）：

```
task_items：7 条，其中 4 条 scope=project、done=1、done_at 有值、spent_sec=0
time_logs：仅 1 条，属于一条 solo 事项（6 秒）
```

项目事项都是在小任务窗口里点「标记完成」结束的，不跑秒就没有 `time_logs` 流水。而 B17 的右栏推进数原先这样算：

```dart
int _projectsTouched(List<TaskDayEntry> entries) => <String>{
  for (final entry in entries)
    if (entry.task.projectId != null) entry.task.projectId!,
}.length;
```

`entries` 来自 `entriesForDay()`，只含有流水的事项，于是项目事项全被漏掉，推进数恒为 0。

完成件数走的是 `doneBetween()`，不分 `scope`，项目事项自然算进去。PRD 第 5 页写的是「完成 5 件 · 推进 2 个项目」并列，件数含项目事项是对的，不是 bug；漏的是推进数。

## 二、修法

「推进」改成两件事的并集：

- 当天在这个项目上开过表（有流水）；
- 当天完成了这个项目里的一件事（有 `done_at`）。

`RecordsNotifier._load` 里先按 `done_at` 攒 `doneProjectsByDay`，再拿流水里的项目键并进去，得到 `projectsByDay`，存进 `RecordsState.dayProjects`；`select()` 也读这一份，点日期不会算法与整月加载不一致。旧的 `_projectsTouched` 删除。

## 三、用例（新增 4 条，共 441 条全过）

| 结果 | 测试 | 判定 |
| --- | --- | --- |
| 通过 | `records_notifier_test` — 项目事项只点「标记完成」、没跑过秒：件数算 1，推进项目也算 1 | `dayDoneCount=1`、`dayProjectCount=1`、`dayProjects` 含该项目；无投入不画色带 |
| 通过 | `records_notifier_test` — 同一天一个项目既开了表又完成了一件：项目只算一次 | 两处来源去重后仍为 1 |
| 通过 | `records_notifier_test` — 只完成独立事项的日子：推进项目数为 0 | 独立事项不占项目位 |
| 通过 | `records_page_test` — 项目事项只点「标记完成」、没跑过秒：右栏照样报推进 1 个项目 | 右栏「完成 1 件 · 推进 1 个项目」，格子有件数、无 `records-bar` |

## 四、真实数据核对

修后按同一口径在用户库上算：

```
2026-10-25  完成 1 件 · 推进 0 个项目
2026-10-26  完成 5 件 · 推进 1 个项目
```

10-26 那 5 件是 4 个项目事项 + 1 个独立事项，推进的是「毕业论文」这一个项目，与实机应当看到的一致。

`dart analyze lib test` 为 No issues found；`flutter build windows --debug` 通过。

## 五、没改的两处

1. 完成件数仍把独立事项与项目事项算在一起，这是 PRD 的「完成 N 件」口径。要分开看，等 B18 把右栏按「独立事项 / 各项目」分组。
2. 只完成、没开表的事项不画色条（PRD「没有投入就不画」），所以那种日子格子只有件数、没有色段。
