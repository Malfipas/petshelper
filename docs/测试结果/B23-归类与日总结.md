### 清洗规则（这一块比提示词更要紧）

归类：只认第一行 → 去「分类：／类别：／类名：／归类：」前缀 → 去首尾引号书名号括号 → 去句末标点 → 命中 `无法归类|无法判断|不确定|不知道|没有合适的类` 返回 null → 按逗号句号切第一句 → 超 `maxCategoryChars`（12）截断。

日总结：去行首井号标题 → 去行首列表符号 → 去 `**` → 三个以上换行压成两个 → 空返回 null → 超 `maxSummaryChars`（200）截断并补「…」。行首只吃空格与制表符不吃换行——第一版用 `\s*` 把段落间的空行一起吞了，测试当场抓到。

### 为什么用按钮而不是自动生成

`SummarizeDay` 一次请求约 400 token，翻日历是高频动作，进去就请求等于把额度交给鼠标滚轮。改成显式按钮后：看得见什么时候在工作（`生成中…`）、点得动第二次（`重新生成`）、我改过的那版不会被悄悄覆盖（`SkipEdited` 回来时把库里那版摆回去）。代价是多一次点击，这一点在验收时会看实机手感。

## 四、实机核对

1. 设置页配好 key → 想法盒里新建一条「投简历给三家公司」，不选分类 → 几秒后左栏出现新分类，卡片贴在它下面。
2. 新建时手选分类 → 不该再发请求，分类保持我选的那个。
3. 记录页对今天点「生成小结」→ 按钮变「生成中…」→ 回来是一段话，按钮变「重新生成」。
4. 把设置页的 key 删掉 → 再点「重新生成」→ 出现流水账，上方一行「未配置 API key，先按随手记整合」。
5. 点开某天总结自己改一句并保存 → 再点「重新生成」→ 我改的那句还在（不被覆盖）。
6. 点生成后立刻切到前一天 → 那段文字不该跟过去。

## 五、缺口

- 归类没有「正在归类」的界面提示：请求要 1–3 秒，这期间卡片显示「未分类」。加提示要动 state 与卡片样式，本轮没做；如果实机上看着像失败，下一轮补一个极轻的灰字。
- 日总结的触发是显式按钮，原型上那块只画了「AI 汇总一段」。若使用者更希望「进去就有」，改成进页面自动跑一次即可，`generateSummary()` 已经是独立的、可复用的动作。
- 验收表 20 条没在真机上跑过，这一项是 B23 完成判定的最后一格。
