## 改了哪些

- `TaskRepository` 加 `moveOrder` / `addToStep` / `assignToStep`，末尾编号统一走 `_tailOrder`（该步最大 `orderIndex` 加一，不按行数，删过中间条也不撞号）。`moveOrder` 只在同一步的未完成事项之间换，到头或不存在都返 `false`，不写库。
- `ProjectListState` 加 `detailTasks` / `movedTasks` / `pendingDone` / `flashTaskId` / `addTaskFor` / `assigningTaskId` / `notes`，`copyWith` 补三个清除位，`clearDetail` 时一并清掉。
- `ProjectListNotifier` 加八个动作：`toggleTaskDone`、`moveTask`、`startTask`、`askAssign` / `cancelAssign` / `assignStep`、`openAddTask` / `closeAddTask` / `addTask`、`saveNote`。取数收在 `_readTasks` 一次读待办与随手记，写完全部「先落库、再 `_refreshTasks` 与 `reload`」，不做乐观更新（勾选那 600 毫秒除外）。
- `collapse()` 从四层变五层：`confirming` → `addTaskFor` → `assigningTaskId` → `flowEditing` → `openId`。
- 新建 `project_todo.dart`：`ProjectTodoRow`（卡片）、`ProjectTodoSection`（整摞 + 筛过的取数渲染）、`ProjectMovedSection`（移入块与选步骤下拉），随手记的 400 毫秒防抖与失焦补写自成一块。
- `ProjectFlowEditor` 每行补第四枚「＋」与行下的 `_AddTaskRow`（回车提交、Esc 取消、40 字上限）。`projects_page.dart` 接上待办区与移入块，「开始」成功后收起主界面并跳面板页。

## 本轮修掉的实现问题

| 问题 | 怎么发现的 | 改法 |
| --- | --- | --- |
| 切筛选后待办区不跟着变 | 写「点一段只留该步」时状态里还是上一条列表 | `tapSegment` / `clearFilter` 改成改完筛再 `_refreshTasks`，并同步改 B14 测试里的调用 |
| 不筛时不同步的事项按 `orderIndex` 交错 | 「不筛列全部」断言拿到 `[A, C, B]` | `visibleTasks` 先按步骤 `index` 再按步内顺序：`orderIndex` 只在同一步里有意义 |
| 新增后的 1.2 秒闪烁定时器没人收 | 页面测试收尾报「Timer is still pending」 | 换成可取消的 `Timer`，`ref.onDispose` 里收掉，连续新增只留最后一下 |
| 另一件在跑时点「开始」会把面板顶掉再失败 | 「第二件在跑时不再接」用例 | `startTask` 先看一眼面板：已有别的在跑就直接返 `false`，连当前事务都不换 |
| 选步骤下拉量到 28 而不是 30 | 移入块用例高度断言 | key 从 `DropdownButton` 挪到外层 30 高的容器：量的是看得见的框 |

## 偏差

| 项 | 原型 / PRD | 实现 | 为什么 |
| --- | --- | --- | --- |
| 新增后滚动 | 原型未写滚动行为 | 滚到该条居中（200ms） | 待办多时新增的那条常在视口外，不滚过去就看不出「加上了」 |
| 待办排序 | 原型按 DOM 顺序 | 步内按 `orderIndex`，跨步先按步骤顺序 | 卡片可 ↑↓ 调序，DOM 顺序不再等于数据顺序 |
| 移入块的行高 | 原型稍矮 | 与待办卡同为最小 72 | 两块上下相邻，行高一不一样就看得出接缝 |
| 「选择步骤」再点一次 | 原型未定义 | 收起下拉 | 同一颗键兼作开关，少一个取消入口 |
| 待办区件数 | 原型待办区无件数 | 不写 | FR-15：件数只在移入块头写一次 |
