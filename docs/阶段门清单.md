# 阶段门清单

**这是唯一的判定入口。** 所有"这段做完了吗"的问题只看这里。

三条规则：

1. 全部勾选才进入下一阶段；
2. 任何一条没勾，回到该阶段末尾写明的**回退点**；
3. 不允许"差不多就行"。

**怎么用**：把 `[ ]` 改成 `[x]`，并在每条末尾的「证据」位置写上东西在哪（文件路径、截图、日期、具体那件事）。证据写不出来，说明这条还没过。

## 01 · 立项与边界

> **核心问题**：我到底在为谁解决什么问题？我为什么会失败？
> **回退点**：起点阶段。定位那句话写不出来，就停在这里，不要进阶段 02。

**A 产出物存在且完整**
- [x] 一句话定位：为谁、解决什么问题 · 验证：读出来，"并且"不超过 1 个
- [x] "不做什么"至少 3 条 · 验证：每条说得出来砍掉它的理由
- [x] 对自己的失败预判 + 对应应对 · 验证：预判具体到场景，不是"我可能会放弃"
- [x] 本轮不做的事（例如技术选型、界面实现）· 验证：边界清楚，别人读了知道去哪找
- 证据：`01-立项与边界.md` 的四节：「一句话定位」「不做什么」（四类共 7 条）「失败预判」（制作期、使用期两条）「本轮不做的事」（5 条）

**B 有证据**
- [x] 定位那句话写在文件首屏，不只是存在于对话或脑子里 · 验证：打开文件第一屏就能读到
- 证据：`01-立项与边界.md` 首屏的「一句话定位」一节

**C 下游输入齐备**
- [x] 阶段 02 拿到这份边界，知道自己该观察什么、不观察什么
- 证据：四类"不做什么"即观察边界；`02-用户调研.md` 已按此范围收集场景

**D 核心问题写死**

## 02 · 用户调研

> **核心问题**：启动不了 / 决策内耗 / 留不住东西，这三件事在我身上具体长什么样？
> **回退点**：某类痛点凑不出真实场景，说明它不是你的真痛点。回阶段 01 调整定位，别硬填。

**A 产出物存在且完整**
- [x] 三类痛点，每类至少 1 个**真实发生过**的场景（不是想象的）；第 1 类的三个子状态各至少 1 个 · 验证：每个场景能说出当时大概什么时候、在哪、正在做什么
- [x] 每个场景写明：卡在哪一步、当时的应对、应对为何失效 · 验证：三项都在，不缺
- [x] 假设清单，每条写成可被推翻的句式 · 验证：读一遍，能想象什么情况会让它不成立
- [x] 痛点优先级排序（不并列）· 验证：能说出最痛的那一类，以及为什么是它
- [x] 现有替代方案扫描：番茄钟类 / 习惯打卡类 / 待办类，各自覆盖到哪、又在哪里失效 · 验证：有来源或你亲历的记录
- 证据：`02-用户调研.md` 的「三类痛点与真实场景」（三个子状态各含一张场景表）、「假设清单」（7 条，各带推翻条件）、「痛点优先级」（三类排序）、「现有替代方案扫描」（含来源与证据强度）

**B 有证据**
- [x] 场景来自真实经历 · 验证：翻回去看能回忆起当时的情形，不是"应该会有这种情况"
- 证据：场景均出自使用者本人的经历叙述，已逐条确认为属实

**C 下游输入齐备**
- [x] 阶段 05 拿到按优先级排好的痛点清单 + 每类的具体场景（这是功能追溯矩阵的唯一来源）
- 证据：`02-用户调研.md` 的「痛点优先级」一节即排序后的清单，各场景表即追溯来源

**D 核心问题写死**
- [x] 一句话写死"最痛的是哪一类，它为什么现有工具解决不了"
- 证据：最痛的是**启动不了**。现有工具都在回答"该做什么"，而它卡在"真的开始"那一下；规划与启动是两种不同的能力，所以规划类工具从原理上修不了它
