## 二、背景与目标

### 2.1 背景

**这个人群的基本盘。** ADHD 是注意缺陷多动障碍，核心是执行功能发育滞后。与本产品直接相关的有三条：启动困难，知道一件事重要却抬不起手；时间盲区，估不准一件事要多久，也感觉不到时间在走；工作记忆容量小，做完的事转头就忘，想到的事转眼就没。中国成人患病率约 3%，对应人口超过 2000 万；儿童患病率 6.4%，约 65% 的症状延续到成年（2024 版成人诊疗指南的转述，二手）。

**时代给这个人群加了杠杆。** 信息流与短视频把注意力切成越来越短的片段，普通人也在出现同一种症状：坐下打开电脑，本来要做正事，先刷十分钟，刷完更不想开始。专业上叫注意力碎片化，日常说法是"知道该干活了，但身体不动"。

**这个产品解决什么。** 它不回答"该做什么"，那件事待办清单已经做得很全。它只做一件事：在你卡住那一刻自己出现，把"该做什么"压缩成"现在做这一步"，并且不要求你想起它、打开它、先做一份计划。

**它的意义。** 对确诊的人是执行功能的外部补偿件，相当于把前额叶缺的那一段挪到桌面上。对没确诊、但在碎片化里逐步失去专注的人，它是一道提前装上的护栏。

**这个品类在国内的现状。** 四类工具各占一角：通用待办解决"别忘了"，番茄钟解决"开始之后怎么撑住"，ADHD 辅助应用解决"怎么拆"，通用 AI 助手解决"问得到"。八家竞品逐家分析下来，没有一家把这三件接起来：出现、拆开、看得见（见 04 的总判断）。豆包已经做到常驻桌面，点开却是一个对话框，任务散在聊天记录里翻不回去。ADHD 专用工具在国内接近空白，PlanCoach 是唯一一个把"拆到能动"做成主打并起量的。


### 2.2 目标

具体做这十一件事（对应 4.2 的 F1 到 F11）：

1. 开机后自己出现在屏幕边缘，不用我去打开
2. 在桌面上直接显示今天要动的那一件事，不铺列表
3. 提醒只有两档气泡：截止强提醒，与开机时的项目现状播报
4. 点"开始"之后，界面上只剩这一个动作
5. 把这个动作拆到我不用下决心，并报出大概要多久
6. 我停手之后自动记一条流水，不填任何字段
7. 记录改错了可以改，改了留痕
8. 我在别处选中或复制的一段话，能收进某个项目
9. 有一个装得下这些事的项目容器
10. 每天把流水梳理成进度史，并能生成一段能对外讲的话
11. 日历上按投入分布着色，能看出每天在哪个项目上花了力气

两件都值得做时怎么选、两件截止撞了怎么提示，这两件不在 v1，已登记进 [v2 候选清单](v2候选清单.md)。

**用什么衡量。** 五条指标：

| 指标 | 目标 | 口径 |
| --- | --- | --- |
| 每周使用天数 | 4 天±1 | 当天只要有过一次点开或点开始，就算用过 |
| 每周点开始次数 | 8 次±3 | 点一次"开始"记一次 |
| 点开始后执行满 5 分钟的比例 | 40%± | 5 分钟是"真的开始了"的最低线，低于它算点了个寂寞 |
| 出现到点开的比例 | 40%± | 桌面出现算一次曝光，点开算一次转化 |
| 次日再出现的比例 | 70%± | 借鉴办公类应用次日留存 60%-70% 的公开区间 |


## 三、故事介绍

### 3.1 用户场景

十二条功能级场景，每条对应 4.2 的一个功能编号：

1. 用户可以不做任何操作，就在屏幕右缘看到助手，并且看到今天要动的那一件事（F1、F2）
2. 用户可以把鼠标停在助手身上，看到这件事在整条流程里第几步，以及这一步大概多久（F2）
3. 用户可以点"开始"，界面随后只剩这一个动作，不再出现别的入口（F4）
4. 用户可以随时点"停了"，不做结算、不看进度条、不看倒计时（F4）
5. 用户停手后，助手自动记一条流水，不需要确认、不需要填字段（F6）
6. 用户可以在别处选中一段文字或复制一段话，把它收进某个项目（F8）
7. 用户可以在项目里看到梳理后的进度史，每条带时间戳（F10）
8. 用户可以点某条记录看到它的修订链，知道自己改过什么（F7）
9. 用户可以让助手把一个项目讲成一段能直接对外说的话（F10）
10. 用户可以在日历里看到每天各项目的投入分布与完成件数（F11）
11. 用户可以在截止前与开机时收到两种气泡：前者不可忽略，后者播报各项目现状（F3）
12. 用户可以点开助手，进入主界面看到所有项目卡片与模块入口（F2、F9、F11、F12）

**这个产品不做的场景**：

- 不提供一次显示多件事的列表，任何界面都不出现"你还有 N 件"
- 不做强制锁机、不做排行榜、不做连续打卡惩罚
- 不收文件与图片，想法盒只接文本
- 不自动归类，收进来的想法由我选项目
- 不在执行中弹窗、提醒、报时
- 没有填模型 key 时，三处 AI 入口用不了：面板里的问一问、拆解（F5）、梳理（F10），其余照常：出现、提醒、记录、日历都能用。界面把这种情况说成"还没配置"，不说成出错
- 所有 AI 入口在未配置时表现一致：输入框只读、占位或提示文字指向设置页、发送与生成按钮禁用，含选文件、选图片这类附件入口；后续页面的梳理按同一条执行
- 模型慢、超时或断网时同理：这几项直接不启动，不拿别的动作顶上，其余功能照常
- 所有 AI 输入框按回车发送；第 2 页是textarea，Shift+Enter 换行；输入法上屏的那一下回车不算发送
- API key 在设置页（第 8 页）填与清：保存后各页 AI 入口立即恢复，清除后一律回到只读
- AI 梳理类回复按固定结构返回：一句 `reply` 加一个 `steps` 列表，每项含步骤名 `name` 与这一步要做的 `task`。界面把 `steps` 渲染成列表并给一个「应用到项目」；接真实接口时照此结构返回，写入逻辑不变
- 随手记三个入口（小任务窗口、独立事项编辑页、项目待办编辑页）共用一份，按事务 id 存进 `scratchNotes`；执行中问过 AI 再记一个 `aiUsed`，第 5 页的 AI 总结拿这两样做原料。项目待办与独立事项用的是同一块编辑页

### 3.2 价值分析

**桌面常驻式桌宠做入口，事情的被看见概率大大提高。** 它不需要我想起、不需要我打开、不需要系统通知权限，坐在电脑前它就在那儿。产品每周使用天数有望达到 4 天甚至更高，出现到点开的比例有望到 40%±。

**下一步拆到抬手就能做，决定"做不做"的成本从评估变成照做。** 原来要先想清楚整件事怎么走，现在只要看这一句。点开之后走到点开始的比例有望 60%±，一周下来点开始的次数有望到 8 次±3。

**界面只留一个动作，没有第二个选项可挑。** 点开之后不存在"再选一个"这一步，选错和返工的机会一起消失。点开始后执行满 5 分钟的比例有望 40%±。

**停手不结算，昨天没做成不变成今天不敢看。** 没有进度条、没有倒计时、没有结算动画，失败感没有落脚点。次日再出现的比例有望 70%±。

**记录与梳理全自动，攒下来的东西不会白攒。** 这条不对应某个具体数字，它保住的是前面几条的成果：昨天做过的事还在，今天才有理由再出现一次。

**这些数字的把握。** 同类公开基准给的是办公类应用次日留存 60%-70%、推送打开率 20%-40%，上面的推断都在这个量级里，不离谱。


### 3.3 核心体验路径

```
出现 → 点开 → 看懂这一步 → 点开始 → 执行
   → 点停 → 自动记录 → 晚上梳理 → 下次出现带着上次的痕迹
```

这条链只有一条主干，不分支。

链上每个箭头都是一个转化点，都能用一条埋点测到（见 6.1）。哪一环掉得最多，下一版就改那一环，不改别的地方。

### 3.4 产品指标预测

按 3.3 的链逐步预测。

| 环节 | 预测 | 猜的依据 | 主要失败原因 |
| --- | --- | --- | --- |
| 出现 → 点开 | 40%± | 推送打开率公开区间 20%-40%，桌面常驻的接触成本更低，取区间上限 | 位置被窗口挡住；显示的不是当下能做的事；天天同一句看腻了 |
| 点开 → 点开始 | 60%± | 已经点开说明有意图，剩下的是动作够不够小 | 这一步还是太大；项目选错；看到的是昨天没做完的那件，不想面对 |
| 点开始 → 执行满 5 分钟 | 40%± | 拆解质量决定这一环，同类产品靠"拆到动词级"把门槛降到抬手 | 拆得不够小；被消息打断；点开始只是给自己一个交代 |
| 停手 → 自动记录成功 | 95%± | 不经过网络、不需要确认，只有进程被杀会丢 | 强制结束进程；跨零点的时间归属算错 |
| 当天 → 梳理生成 | 90%± | 有流水就能梳理，模型超时是主要风险 | 当天流水为空；模型调用超时 |
| 次日 → 再次出现并点开 | 70%± | 办公类应用次日留存 60%-70%，自用产品少一层获客损耗 | 昨天没做成带来的自责；忘了它在屏幕哪一边 |

**一周的账**：35 次曝光 × 40%± = 14 次点开；14 × 60%± = 8 次点开始；8 × 40%± = 3 次执行满 5 分钟。这三个数就是 2.2 里的目标值，两边同一套算法。

### 3.5 路径规划

**开发时给移动端（iOS、Android）预留适配空间。** 具体做法是数据层与界面层分开，界面尺寸与交互不写死桌面专属的绝对像素，键盘与鼠标的操作都有对应的触摸替代路径。除此之外本节不写别的。

## 五、详细设计（页面原型）

八个页面，每页六段：什么时候出现、屏幕上有哪些元素、大致布局、能做的操作、状态变化、不要做什么，末尾标出它服务的功能与需求。

**这份文档只描述要画什么。** 第 1、2、3 页已有可点的 HTML 原型，都在 `prototype/` 下，方向 A 系统原生；其余页面先按要点画，原型逐页补。原「选择对比」已移出 v1，见 [v2 候选清单](v2候选清单.md)；原「执行中」并入第 2 页的悬停面板，第 4 页现为独立事项。

**原型怎么组织**：每页先独立改，改完合进 `prototype/整体原型.html` 看合起来的效果。分页文件与整体文件互相有入口，验收时先看单页、再看整体。三页都已并入；整体原型里点桌宠开的是五标签主界面，气泡"查看"跳转时自动切到"我的项目"页。

### 第 1 页 · 桌面常驻态

**什么时候出现**：开机自启动后一直在，不需要我做任何事。

**屏幕上有哪些元素**

- 收起形态：贴桌面右缘用 `常驻右-240.png`，占桌面短边 15% 的正方形框，图片等比缩放，手指握着屏幕边，脸从边后探出
- 展开形态：`展开-360.png`，占桌面短边 25% 的正方形框，同样贴右缘，切换时以右下角为锚点放大
- 头顶气泡：两档提醒长在这里。以宠物为基准定位：气泡右边缘压进宠物图左边缘 15 像素，往屏幕内侧展开，气泡栈底边落在宠物顶部下方 5 像素；单个气泡宽 25% 屏宽、最高 30% 屏高，超出在气泡内部滚动；两档同时出现时上下排开、间距 8 像素

### 第 2 页 · 悬停小面板

**什么时候出现**：光标停在宠物身上 300 毫秒后出现，移开 500 毫秒后收起。宠物形态不变。光标在面板里、或输入框还在聚焦时一律不收起，避免打字打到一半面板消失。

**屏幕上有哪些元素**

分两种形态，取决于当前事务属于哪一类。

形态 A，当前事务在一个项目里：

- 项目名，旁边一个"已标记"的角标
- 总流程轴：按这件事的实际总步数生成一排胶囊条，走了的与正在走的填蓝，没开始的留浅灰。段上不写字，悬停某一段才浮出"第 N 步 · 这一步的名字"
- 这一步的一句话，以及预计时长
- AI 帮助：一个输入框，提示词写"有什么我能帮助你的吗？"，右侧发送键是一个纸飞机图标；输入框随内容长高，到四行封顶后内部滚动；问一句就地作答，答案以气泡形式留在面板里
- 底部一个"开始"按钮，下面一行"标记完成"

形态 B，当前事务是独立事务：

- 事务名，以及一行"独立事务"，同样带"已标记"角标
- AI 帮助：同一个输入框
- 底部一个"开始"按钮，下面一行"标记完成"

**显示的是哪件事**：面板里是当前的这一件，点「开始」的那件就是当前——独立事项与项目待办都照这条，点谁就开始谁。不按时间、不按截止、不按谁更急去猜。项目待办进来时面板换成形态 A：项目名、这条所属步骤的流程轴、这一步是什么。没有当前事务时（列表空、全做完、刚删完），面板只留一句"当前无正在进行的事务"，下面一行小字"点桌宠进主界面挑一件"，其余部分都不显示。

**没配置模型 key 时**：AI 输入框只读，占位文字换成"请前往设置页配置 API key"，右侧发送键禁用并置灰；点输入框不弹输入，只在事件里记一次。面板其余部分照常。

**独立事务怎么来**：第 4 页「新建事项」建出来的直接就是独立事项；别处新建时才选归到项目还是独立。两边不互相搬运——「移到项目」始终没做出来，2026-10-26 起明确撤掉，独立事项就一直归独立事项。

**大致布局**：贴在宠物左侧的小面板，宽 25% 屏宽、最高 35% 屏高，超出在面板内部滚动。定位同样以宠物为基准：面板右边缘压进宠物图左边缘 15 像素，顶部从宠物顶部下方 5 像素起。宠物只贴右缘，面板一律向左展开，不越过屏幕中线。

**能做的操作**

- 点"开始"：按钮原地换成计时条，左边是当前耗时并精确到秒，右边是暂停与停止两个图标按钮。暂停用两条竖杠，继续用三角形，停止用方块且底色是红的；都不带文字，靠形状和颜色认
- 点暂停：只停表，数字转灰、图标切成三角形；再点接着走，已走的时长不丢，不标完成
- 点"停止"：停表并把这件标为完成，这一次的时长按流水记下来；独立事项的面板回到空态，项目事项换到下一步
- 点"标记完成"：把这件标记为已完成，面板收起
- 点"拆小一点"：这一步换成更小的一个动作，面板就地换，不跳页
- 在 AI 帮助里输入：就地作答，不跳页；回车发送，Shift+Enter 换行；问得多时问答区在面板内滚动，面板本身不再长高；问过 AI 的那件事会记下「用过 AI」，第 5 页的总结以它为依据
- 在「随手记」里写：计时中随时记一句这一步的成果，失焦保存，跟着这条事务走；独立事项与项目事项的详情里写的也是同一份
- 点项目名：进入第 6 页我的项目，并展开这个项目
- 按 Esc 或移开光标：收起，回到常驻态；正在跑的计时不因收起而停

**状态变化**

| 状态 | 表现 |
| --- | --- |
| 有下一步 | 显示位置、这一步与时长、"开始"按钮 |
| 没有下一步 | 显示"这个项目暂时没有下一步"，给一个"现在想一件"的入口 |
| 计时中 | 计时条取代按钮，左边走秒（到秒），右边暂停与停止两个图标 |
| 已暂停 | 计时停住、数字转灰，暂停图标变成三角形；点它接着走，不标完成 |
| 已完成 | 显示"这件事已标记为完成"，不再给开始与跳过 |
| 切到另一件事 | 面板换内容，原来那件的计时照跑；两件的秒数各算各的 |
| 没配置模型 key | AI 输入框只读、占位文字指向设置页、发送键不可点 |
| 没有当前事务 | 面板只显示"当前无正在进行的事务"与一行引导 |
| 加载中 | 显示上一句话，不显示转圈 |

**不要做什么**

- **不显示未完成计数**。这里禁的是"你还有 12 件没做"这类件数，气泡里的项目现状不在此列
- **不给列表**。一给列表，选择就又回到我头上
- 不显示进度条，不显示项目切换器
- 不做倒计时与"还剩多少"；停下不结算、不弹窗表扬或催促
- 悬停不改变宠物形态，形态只在点击时切换
- **AI 的回答只在面板里当参考**，不替换上面的下一步，也不生成新动作。要改下一步，走"标记完成"或回到项目里改
- **对话按事务隔离**：一段对话只属于它所在的那件事，同一项目下的两件事也各存各的，切过去看不到对方的历史
- **计时也按事务隔离**：一件在跑不影响另一件，也不合并成总时长

**对应功能与需求**：F2、F4、F5 ｜看得见、能启动。

**已通过的原型**：`prototype/第二页-悬停小面板.html`，2026-10-21 定稿。可切两种形态与 3／5／7 步，流程轴悬停出步骤名，另设「同项目的另一件事」用来验证对话隔离。2026-10-22 补：AI 未配置 key 时只读提示、发送键禁用；面板加了空态，控制条一个开关可切「无当前事务」看提示。已并入 `prototype/整体原型.html`。

### 第 4 页 · 独立事项

### 第 5 页 · 我的记录

**什么时候出现**：点主界面的「我的记录」标签进入；默认停在今天。

**屏幕上有哪些元素**

- 左栏月历：月份条（`‹` 年月 `›` 与「今天」）、周标题、6×7 网格、底部图例
- 每个格子：日期数字、当天完成件数（0 件不写）、底部一条 3 像素分段色条。没有投入就不画
- 色条规则：**独立事项固定灰**，永远占第一段；项目按新建先后取固定颜色，六个一轮回（蓝／青／紫／橙／粉／天蓝），同一项目每天颜色不变；每天最多画 4 个项目段，再多合并成一段浅灰蓝的「其他项目」

- 条目默认收起：只露事名、时长与时间，右侧一个 `›`；点整行展开 AI 总结与感想，箭头转 `⌄`，再点收起
- 每条事项的 AI 总结按四态显示：改过就显示用户写的；配了 key 且这条用过 AI，显示「对话 + 随手记」整理出的总结；没配 key，降级成随手记原文并留「未配置 API key，先按随手记整合」；配了 key 但没用过 AI，就留白，只给「写总结」入口。四态都带「编辑」

- 点月份两侧的 `‹` `›`：换月，选中落到该月 1 号
- 点「今天」：回到今天并选中

| 有记录 | 头部给件数与推进项目数，按组列出事项与 AI 整理 |

**不要做什么**

- 不显示「连续未打卡多少天」，不在格子上写评价性文字
- 不做「改正流水」与修订链。这一页只做回看与写感想，改记录回第 4 页或第 6 页去改
- 不做导出，不在这一页放 AI 对话框；AI 只负责每天整理，不接受追问
- 不把第 4 页已完成的事项搬成一页清单。这里按天汇总，同一件事只在当天出现一次

### 第 6 页 · 我的项目

**什么时候出现**：点主界面的「我的项目」标签进入；从悬停小面板点项目名也落到这一页，并直接展开那个项目。

**这一页有两种形态**

- 列表态：一行一个项目，点哪一行就地展开
- 展开态：被点的那一个占满整个页面区，列表其余部分隐藏；左上「← 全部项目」回到列表

**列表态的元素**

- 页头：标题「我的项目」与一行件数，右侧「新建项目」
- 项目行：单列宽行，行高 88、圆角 12、间距 8。行内三行文字：项目名与百分比、4 像素细进度条、「下一步：…」与「最近推进：…」；右侧一个轻箭头提示可以展开
- 点「新建项目」后，标题下方就地展开一张表单，不弹窗、不跳页

**展开态的元素**

- 顶部：`← 全部项目`、项目名（20 像素、字重 600）；项目名右侧依次是一句话说明与截止日期（写「截止 10 月 30 日」，没有就整段不显示）；下面一行进度（`42% · 已完成 3/7 步 · 最近推进 昨天`）；最右一个「删除项目」。这一页不放「讲给我听」
- 分段进度条：与第 2 页悬停面板同一套——段数等于步骤数，已完成的段用主色，其余 `#d8e0ec`，高 5、圆角 3、间距 5；每一段都可点。新项目的流程初始只有一个空步骤，名字由用户自己填，没填时显示「未命名步骤」
- 进度条右侧一个「编辑流程」，点开就地出现步骤列表
- 筛选提示行：选中某一段时出现「第 3 步 · 写结论 ×」，点 × 或再点同一段取消
- AI 帮助：默认收起成一行「AI 帮助」，展开后只有「选文件」「选图片」两个按钮，下面是资料 chip、对话流与输入行；发送键是纸飞机图标
- 待办：不写区块标题；进页面默认只显示当前正在推进那一步的事务。卡片样式与第 4 页一致——多选框、事名与元信息、中间说明、右上「↑↓」调序、右侧「开始」，卡片里还有一行「随手记」。**页面上没有项目级的开始按钮**，开始只挂在每条事务上
- 从独立事项移入：这一块在待办之下、进度史之上，只收还没有步骤归属的事务（刚移进来的、以及步骤被删后落单的）。每条带来源角标、说明与「选择步骤」，随手记跟着搬过来，没有就整块不显示
- 进度史：只按流程顺序排，右侧一个「时间轴」切换；每条左侧时间戳、中间一句进展、右侧步骤标签；改过的带「改过 N 次」；每条还有一个「随手记」按钮，任务完成后随手记跟到这里，还能接着改
- 待办为空时，这一块留白，不写提示、也不给输入框；要加事走「编辑流程」里的「＋ 事」或 AI 梳理

**大致布局**：壳仍是 70%×70%，最小 880×560，整块居中。正文单栏、内部滚动。待办卡片最小 72 像素高、圆角 12、间距 8，名称列占 42%、说明占中间；进度史时间戳列固定 88 像素宽；AI 对话区最高 220 像素，超出在内部滚动。圆角沿用壳 18、正文 14、卡片 12、按钮 10。

**能做的操作**

- 点「新建项目」：标题下方展开表单，三项——项目名（必填，最多 30 字）、一句话说明（选填）、截止日期（选填）。项目名为空或与已有项目重名时「确定」置灰，重名时下面多给一行提示。确定后新项目插在列表顶部并自动展开进空详情；取消或 Esc 收起表单，不建项目
- 点项目行：就地展开，列表其余部分隐藏，详情占满页面区；同一时刻只展开一个
- 点「← 全部项目」：详情收起，列表回来
- 点进度条第 N 段：待办只列属于这一步的事项，件数改成「4 件中的 2 件」；再点同一段或点提示行上的 × 恢复全部
- 点「编辑流程」：就地出现步骤列表，每步可以改名、上移、下移、删除；底部「＋ 加一步」；点「完成」收起。删掉的步骤里原有的事务转为「未分配步骤」，编号自动前移
- 点某步右侧的「新增事项」：该步骤行下方就地出现一个输入框与「添加」「取消」，回车或点「添加」把这条待办落到这一步，随后把筛选切到这一步、把新增行滚进视野并闪一下；输入为空时「添加」置灰
- 点「AI 帮助」：展开上传按钮、对话流与输入行。可以选文件、选图片，也可以直接把文件拖进来；选中的资料以 chip 显示，可逐个移除。输入后按回车或点纸飞机发送；请求进行中发送键禁用、右上角写「正在梳理」，接不上时气泡里给「重试」
- 发送后 AI 按约定结构回来：一句结论加一组步骤，每项含步骤名与这一步要做的事；气泡里渲染成列表，下面一个「应用到项目」。新项目会用它替换空流程，已有进展的项目把这几步追加在末尾，点一次之后按钮变「已应用」不再重复写入
- 点「删除项目」：弹出确认窗，标题「删除「项目名」？」，下面一句「项目所有数据将被一并删除。」；点「取消」或遮罩关闭，点「确认删除」把这个项目连同它的待办、进度史、移入记录一起删掉，回到项目列表
- 点未归位那条的「选择步骤」：点开是步骤下拉（「第 N 步 · 步骤名」加末项「保持未分配」）；选某一步就把这条挂过去、筛选跟到那一步，它从这一块移到该步的待办里；选「保持未分配」或取消则不改变
- 点待办里的「↑」「↓」：与同一步骤的相邻一条交换位置，用来表达这一步里的先后；到头不响应，其它步骤的顺序不受影响
- 点某条事务的「开始」：壳收起、回到桌面，悬停面板换成这条事务并开始走秒。面板复用第 2 页的计时，只搬计时条与暂停、停止、标记完成，不搬 AI 问一问
- 面板里点「停止」：本次时长累加到这一行并标为完成，面板换到下一步；没有下一步就回空态
- 勾选事务的多选框：先变蓝并给事名加删除线，600 毫秒后从待办移出，并在进度史顶部补一条「完成了「某事务」」；这条随手记一并跟到进度史里
- 点「时间轴」：进度史换成节点视图，再点回来
- 点某条记录：展开它的修订链，不弹窗
- 点某条记录右侧的「编辑」：文字就地换成输入框，改完「保存」写回，进度史与时间轴两处一起变；「取消」或 Esc 不保存

**不要做什么**

- **不在项目级放「开始」**。开始只挂在单条事务上，避免一次点开整个项目
- **新建项目不弹窗、不跳页**。表单就地展开，避免打断列表
- **不同时展开两个项目**。展开即独占页面区
- **进度史只给流程顺序**。不再提供由浅入深、按类型两种排法
- **上传只记文件名**，不读取文件内容、不上传服务器，界面上也不显示文件预览
- **列表空就留白**。待办为空、进度史为空都不写提示语、不放"现在梳理一次"这类按钮；列表里的「下一步」没有内容也留空
- **删除项目必须二次确认**。不做一键直删，也不做成输入项目名才能删
- 列表里不堆统计图表，只留百分比与下一步
- 不默认展示全部流水。默认给的是梳理过的进度史，流水要点开才有
- 不在进度史里显示"你今天没做"

### 第 7 页 · 想法盒

**什么时候出现**：点主界面的「想法盒」标签进入；页名与标签同名。

**屏幕上有哪些元素**

- 左边一列分类：第一行固定「全部」，下面是 AI 解析出来的分类，每项带条数；点分类，右边换成那一类的想法
- 右边是想法列表：每条一张卡，标题加粗、正文两行内、右下角是收进来的时间与分类小标签
- 页头：当前分类名与条数，右侧一个「新建想法」
- 编辑态的卡片：标题输入、正文输入、一个分类下拉、「存下 / 删除 / 取消」

**大致布局**：沿用主界面壳（70%×70%，最小 880×560），五标签里「想法盒」选中。正文左右两栏，左 24%（分类列）＋右 76%（想法列表），中间一条分隔线，两栏各自滚动。卡片圆角 12、细边框，悬停时边框变深、轻微浮起。事名 15、正文 13、元信息 12；圆角沿用壳 18、页面 14、卡片 12、按钮 10。

**能做的操作**

- 点「新建想法」：列表顶部展开一张编辑卡，写标题与正文，点「存下」入库并收起；标题为空时「存下」置灰
- 点某条想法：就地进编辑态，改标题、改正文、换分类，或删掉它
- 删：点「删除」按钮变成「确认删除」，再点才真删，左栏计数同步
- 存下之后 AI 解析标题与正文，把这条归到某个分类，每条只自动分一次；之后再编辑不重复分，除非手动换分类
- 改分类名：左栏分类旁点「重命名」，行内输入后保存，这一类想法的标签跟着改
- 搬想法：编辑态里换分类下拉，存下即移到那一类

**状态变化**

| 状态 | 表现 |
| --- | --- |
| 有想法 | 列表按收进来时间倒序，每条带分类标签 |
| 没有想法 | 一句「这里还没有想法」加一句「点右上角『新建想法』记一条」 |
| 没配置模型 key | 分类列表照旧显示，只是 AI 归类这个功能停掉：不再给新想法自动分类，卡片标「未分类」；编辑态的分类下拉仍可用，用户自己搬想法，旁边留一句「未配置 API key，AI 不再自动归类」 |
| 想法刚存下 | AI 稍后归类，卡片右下出现分类标签，左栏对应分类计数加一 |
| 分类被改名 | 该类所有想法的标签同步改名 |
| 删除确认中 | 按钮变红并写「确认删除」，三秒内没点就还原 |

**不要做什么**

- **不让用户手工新建分类**。分类只来自 AI 解析，用户只管改名与搬想法
- **每条想法只自动分一次**。反复解析会把用户的搬动打乱
- 不显示「你还有几条没处理」
- 不在想法盒里做全文搜索，不做导出

**对应功能与需求**：F8 ｜理得清。

**已出的原型**：单页原型 `prototype/第七页-想法盒.html` 2026-10-23 出稿，已并入 `prototype/整体原型.html`，整体原型现在含第 1 到第 7 页，验收看整体原型。整体里点「想法盒」标签就是这一页：左分类右想法两栏；新建走行内卡片、标题必填；点想法就地编辑，可改标题正文、换分类、两段式删除；保存后 mock 一次 AI 归类，每条只分一次；左栏可给分类重命名，分类用 id 关联，改名不牵连想法；没配 key 时分类照旧显示，只是 AI 归类停掉。

### 第 8 页 · 设置

**什么时候出现**：主界面顶部「设置」标签。页名与标签同名。这一页只有两件事：模型 API key，与本项目的两个地址。

**屏幕上有哪些元素**

- 页头只有标题「设置」，不放副标题
- 卡片一「模型 API key」：字段标签「API key」、一个默认掩码的输入框、一个切换明文的眼睛按钮、「保存」「清除」两个按钮
- 卡片二「项目地址」：两行只读输入框，「演示视频」与「项目仓库」，各带一个「复制」

**大致布局**：沿用主界面壳，五标签里「设置」选中。正文单栏，两块卡片纵向排，卡片白底、圆角 12、细边框，块间距 20 像素。输入框高 38、圆角 10，聚焦描主色；主按钮实心主色，次按钮描边。没有侧栏，没有分区导航，卡片内不放说明性文字。

**能做的操作**

- 填 key 后点「保存」：写进本地存储，按钮变「已保存」1.5 秒后复原；各页 AI 入口随即恢复
- 点「清除」：删掉 key，按钮变「已清除」1.5 秒后复原；各页 AI 入口按 3.1 的统一规则回到只读
- 输入为空时点「保存」：按清除处理，按钮同样显示「已清除」
- 点眼睛按钮：在掩码与明文之间切换
- 点「复制」：把地址写进剪贴板，按钮变「已复制」1.5 秒后复原；剪贴板不可用时退回选中文本并提示手动复制

**状态变化**

| 状态 | 表现 |
| --- | --- |
| 保存成功 | 「保存」按钮文字变「已保存」，1.5 秒后复原 |
| 清除成功 | 「清除」按钮文字变「已清除」，1.5 秒后复原 |
| 空值保存 | 等同清除，按钮显示「已清除」 |
| 复制成功 | 「复制」按钮文字变「已复制」 |
| 剪贴板不可用 | 选中该地址并在事件台提示手动复制 |

**不要做什么**

- **这一页只放这两件事**。快捷键、气泡开关、梳理排序、数据导出、主题、账号一概不做，v2 里要做另开一轮
- 卡片里不放说明性文字与配置状态行，保存与清除的结果只由按钮文字反映
- 不在页面上回显完整 key，事件台也不记
- 地址是只读的，不提供编辑；真实链接定了再替换占位

**对应功能与需求**：F3 的参数、F12 ｜无。

**已出的原型**：单页原型 `prototype/第八页-设置.html` 2026-10-23 出稿，已并入 `prototype/整体原型.html`，整体原型现在含第 1 到第 8 页，验收看整体原型。两块卡片：key 掩码输入＋保存清除（写 `localStorage.apiKey`，同时把 `aiKey` 开关一并打开或关闭，别页的 AI 入口立刻跟着变）；演示视频与项目仓库两条只读占位地址加复制。卡片里不放说明性文字与状态行，保存清除的结果只由按钮文字反映。
