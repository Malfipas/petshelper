# 02 · 用户调研



## 一、结论

**真正卡住的不是"不知道该做什么"，是"知道该做什么，却不知道它要怎么做"。**



问题出在看不见全貌。知道第一步，不知道第二步；手上这点知识在整个流程里处在哪一格，也说不清。于是"太难了"，于是摆烂，把工作软件放后台，前台刷视频。



**把一件模糊的大事变成一张看得见的路径，每次只给一个动作。**

## 二、需求

需求用四个动词概括，另外记着一条 v1 不做的。它们回答"我要拿到什么"，与后面三类痛点回答的"我卡在哪"是同一批事的两种问法，不是两套体系。

| 需求 | 一句话 |
| --- | --- |
| 看得见 | 轻松看到什么时候要做什么，也看清这件事大概几步、我走到第几步 |
| 能启动 | 轻松开始做一件事，不必在前置流程上消耗自己 |
| 记得住 | 轻松知道自己都完成了什么 |
| 理得清 | 完成的事自动归到该在的位置，不用我判断谁属于谁 |

**v1 不做的一条**：原来的第五条「选得动」——两件都值得做的事之间能选出来，凭代价选，不靠熬。它对应的是决策内耗，属于 Kano 里的魅力需求（不做不难受，做了才惊喜），2026-10-22 移出 v1，登记在 [v2 候选清单](v2候选清单.md)。移出理由见下方「摆烂的那个下午」的补记。

**次序即使用次序**：先看见，再启动；做完留得下；留下之后归得清。

**对应关系**：看得见与能启动对启动不了，记得住与理得清对留不住东西；选得动对应的决策内耗，v1 不做。

## 三、场景

### 摆烂的那个下午

```
打开电脑，告诉自己该工作了，但整体怎么做不清楚，网上搜到的都是碎片，干脆工作软件放后台，前台刷视频
```

**2026-10-22 补记（原记录漏了下面这一层，其余不动）**：那天卡住的两件，一件是求职相关的事，一件是配音基本功练习。重要性我很清楚，求职在前，所以本该去做求职；但求职那件事一时不知道怎么开展，就一直拖着，最后两件都没动。按时间算，两件其实可以同时做，我也拿不出"时间不够"这个理由。拦着我的是"重要那件太沉、容易那件太轻"，两件一起做也消不掉这个顾虑。排时间和摆一张对比表都解不了这一格，要解的是让重要那件变得能抬手就做。

### 忘了的笔试

```
QQ 邮箱收到笔试邀请，想着过两天再写，记在心里，过两天忘了，直到截止
```

### 记住的笔试（对照组）

```
手机短信收到通知，手机自带智能体自动建成待办，放在主屏，那天一定想起来
```

**这个对照组的价值**：同一类事，一个忘了，一个记住了。差别不在重要性，在有没有被自动放到眼前。

## 四、证据

| 强度 | 内容 |
| --- | --- |
| 强 | 对照组。同类事两种结果，差别能定位到具体机制 |
| 强 | 前两个场景都有具体细节：放后台、刷视频、过两天忘 |
| 中 | "没有系统的方法论"这类自述，指向清楚，但没落到某一次 |
| 弱 | "我健忘又很懒"这类自我评价，不作依据 |




**已经能分开的一层**：事的规模决定要什么。笔试这种本来就不用想的事，提醒就够；"做一个应用"这种宽泛的课题，只提醒不起作用，得有人先替它把结构搭出来。

## 五、方法与局限

一次深访，四轮追问。没有用问卷，没有第三方数据，样本是一个人。
