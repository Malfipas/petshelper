## 这一阶段要回答什么问题

**用什么实现它？**

## 产出物

技术约束清单、数据模型、架构分层、技术选型。前两份是把界面要求翻译成技术要求，后两份是实施方案。

## 技术约束清单

每一条都来自 05 里的一句界面要求。同一个事实的两面：界面说"不挡视线"，技术说"无边框透明窗口加层级控制"。

| # | 界面要求（05 第五章） | 技术要求 | 难点在哪 |
| --- | --- | --- | --- |
| 1 | 平时只露半张脸，悬停展开 | 无边框透明窗口，可切换鼠标穿透 | 窗口层级与命中测试要精细控制，穿透开早了点不到，开晚了挡住底下 |
| 2 | 只在光标进入范围时抢焦点 | 可聚焦窗口的按需激活 | 时机错了会打断正在进行的输入 |
| 3 | 不占任务栏，托盘可寻 | 托盘图标，隐藏任务栏项 | 各平台实现差异大 |
| 4 | 自己出现，不依赖我打开 | 开机自启动，后台常驻，单实例 | 要处理开机时机与重复启动 |
| 5 | 唤出快捷键不与输入法冲突 | 全局热键注册，注册失败要能检测 | 热键被占用时系统会静默失败，不检测就等于没有 |
| 6 | 气泡不抢焦点，不开独立窗口 | 附着式气泡渲染 | 需要无焦点窗口，且不能盖住输入光标 |
| 7 | 拖拽后记住位置 | 位置持久化，多显示器坐标 | 多屏时坐标可能为负，重启后外接屏顺序可能变 |
| 8 | 全屏应用时不干扰 | 全屏检测，自动降级或隐藏 | 各平台全屏判定口径不一致 |

**这张表的用法**：技术选型时逐条问"这套技术能不能满足"，能满足几条要能数出来，不能含糊过去。

## 数据模型

### 记录的四个层次

| 层 | 是什么 | 能不能改 |
| --- | --- | --- |
| 实体 | 项目、事务 | 能改 |
| 流水 | 一次执行：做了什么、多久、属于哪个项目 | 能改，改必留修订日志 |
| 进度史 | 按项目累积的梳理结果，每条带时间戳 | 能改，改必留修订日志 |
| 可讲述段落 | 从进度史提炼出的成品，用来对着面试官或答辩老师讲 | 能改，改必留修订日志 |

**贯穿四层的规则**：记录可以改正，改正必须留痕。修订日志记两样：改了什么、什么时候改的；同一条记录的所有修订串成一条链。

### 投入量

某天在某个项目上的投入量，**以完成的事务数为主，步骤数做修正**。

**同一个指标同时决定日历格子的分区比例与颜色深浅。** 这条不能破，否则会出现"占比很大但颜色很浅"这种读不懂的格子。

精确权重待实现时定。

### 日历格子的数据结构

一天一个格子，包含：

| 字段 | 用途 |
| --- | --- |
| 日期 | 主键 |
| 各项目当日投入量 | 算分区比例与各块的深浅 |
| 与项目有关的完成件数 | 格子右上角 |
| 与项目无关的完成件数 | 格子左上角，不参与背景色 |
| 是否为空白日 | 判断要不要留白 |

### 事务与项目

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| 项目 | 名称、组织方式、主进度条基数、最长连续 | 组织方式是项目级设置，不是每次梳理时选 |
| 事务 | 所属项目、标题、步骤、状态 | 步骤是可勾选的最小单位 |
| 流水 | 事务、开始时间、结束时间、备注 | 纯事实，不含评价 |

## 架构分层

| 层 | 职责 | 不做什么 |
| --- | --- | --- |
| 界面层 | 八个页面的渲染与交互 | 不含业务判断，不直接改数据 |
| 流程层 | 五条流程的状态机：出现 → 给一步 → 许可 → 拆解 → 记录 → 梳理 | 不做持久化 |
| 领域层 | 项目、事务、流水、进度史、修订日志的规则 | 不知道界面长什么样 |
| AI 层 | 拆解、梳理、可讲述段落 | 不直接读写数据库 |
| 存储层 | 本地数据库读写 | 不含业务逻辑 |

**依赖方向**：界面 → 流程 → 领域 → 存储。AI 层被流程层与领域层调用，不反向依赖界面。

**为什么把 AI 层单列**：它是唯一会失败、会慢、会花钱的部分。单列出来才能给它定单独的验收标准：模型慢、超时或断网时，拆解与梳理直接不启动，界面如实说不可用，其余功能照常。

## 技术选型

### 三项要定的事

| 项 | 要回答什么 |
| --- | --- |
| 语言与界面框架 | 用什么写、怎么做出无边框透明窗口 |
| AI 模型与调用方式 | 用什么模型、走云还是本地、拆解的延迟能压到多少 |
| 数据存储 | 用什么存、存在哪、怎么备份 |

**每一项都要写清备选与排除理由。** 只写"选了 X"不算选型，要写"为什么不是 Y"。

### 判断依据

| 维度 | 说明 |
| --- | --- |
| 我的熟练度 | 已接触：C++、C、Java、JavaScript、HTML、Python、Kotlin、ASP.NET、XAML。**不碰完全陌生的语言** |
| 开发效率 | 主要靠 AI 生成，我负责判断和调试。生态好、报错容易搜到的优先 |
| 后续维护 | 个人长期使用，两年后我还能看懂 |
| 内存占用 | 桌面常驻程序，不能吃掉几个 G |
| 响应速度 | 唤出要快，拆解不能等太久 |
