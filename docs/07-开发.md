# 阶段 4 · 开发（含 AI 能力）

> **骨架 + 待填。**
> 这是唯一一个产出"能跑的东西"的阶段，也是唯一一个容易跑偏成"永远做不完"的阶段。

## 目标

做出能天天用的最小闭环。

"最小"和"能天天用"两个词都不能丢：只最小、不能用，等于没做；只追求能用、不设边界，等于做不完。

## 这一阶段要回答的核心问题

**最小可用闭环跑通了吗？AI 的表现够用吗？**

## 第一件事：把"闭环"这个词落到具体

**核心闭环 = 启动 → 规划 → 执行 → 记录 → 回顾**

这五步来自[阶段 3](06-设计.md)的五条核心流程。这一步要做的，是把它落到"产品里具体长什么样"。

| 步骤 | 在我的产品里具体指什么 | 做到什么程度算通了 | 状态 |
| --- | --- | --- | --- |
| 启动 | | | |
| 规划 | | | |
| 执行 | | | |
| 记录 | | | |
| 回顾 | | | |

**"通了"的判定基准**：不靠手动兜底。手工往数据库塞一条数据、每次自己去改配置文件、记录要靠事后补，这些都算没通。

## 数据持久化

数据库用 SQLite，文件落在应用数据目录下的 `app.db`（Windows 上是「文档」目录，即 `getApplicationDocumentsDirectory()`；本机被重定向到 `D:\我的文档`，文件就在 `D:\我的文档\app.db`）。关掉重开都在。

| 存什么 | 存在哪 | 关掉重开还在吗 |
| --- | --- | --- |
| 项目、步骤、事项、流水 | SQLite `app.db` | 在 |
| 随手记、日总结、想法与分类、对话 | SQLite `app.db` | 在 |
| 设置项（气泡开关、位置、URL 占位） | SQLite `app.db` | 在 |
| API key | Windows DPAPI 加密后落应用支持目录下的 `api_key.bin`，不进数据库、不进日志 | 在 |
| 桌宠图片等素材 | 应用目录 `assets/`，随安装包走，不落用户数据目录 | 在 |

不存的内容：剪贴板历史、屏幕内容。随手记与对话都由用户主动触发，不后台采集。

**这一条要在阶段 6 的隐私说明里照实写出来**，所以现在就定清楚：发出去的只有用户主动触发 AI 时的那一段文本与标题，API key 经系统加密存在本机（Windows 上是 DPAPI 加密的 `api_key.bin`），数据库文件不上传、不同步。

## AI 能力（子章节）

AI 能力不单独成阶段，但**必须独立验收**。理由是：AI 输出不确定，"能跑"不等于"可用"。

**记录表在这里**：[AI能力验收表.md](AI能力验收表.md)（空表模板在 [模板/AI能力验收表.md](模板/AI能力验收表.md)）

### 能力清单

| 能力名称 | 它在我做哪件事的时候出现 | 对应哪类痛点 | 这个版本做不做 |
| --- | --- | --- | --- |
| 项目拆解（F5） | 新建了项目、只知道大目标，要在详情页把它拆成能动手的几步与几步下的事项 | 大目标落不到今天具体做哪一件 | 做（已接通） |
| 问一问（F4） | 正在做某一步、卡住了，就地在小任务窗口问一句 | 中途要切出去搜，回来找不回上下文 | 做（已接通） |
| 想法归类（F8） | 想法盒里攒了几条，想让它们自己归到分类里 | 事后翻不回、越攒越乱 | 做（B23：新建存下后归一次；成功才落分类，没配 key 不送） |
| 日总结（F10） | 一天结束时想看这一天的一句话总结 | 说不清今天做了什么 | 做（B23：点「今日小结」右侧的生成键发一次请求；没 key 或没答成降级成随手记整合并留一行说明） |

**硬性要求**：说得出"它在我做哪件事的时候出现"。说不出这句话的能力，这一版不要做。它会变成一个没人用的按钮。

### 模型选型取舍

用 [模板/决策记录.md](模板/决策记录.md)。三个维度必须都表态：

| 能力 | 模型 | 成本 | 延迟 | 隐私（数据出不出本机） | 为什么这么选 |
| --- | --- | --- | --- | --- | --- |
| 项目拆解（F5：拆到能动手） | 中档对话模型 | 每次几分钱，一天几次 | 3 到 10 秒 | 出本机：项目名与说明、已有的步骤名 | 拆解要的是结构稳定，便宜的快模型容易漏步骤 |
| 想法归类（F8） | 轻量档模型 | 每条想法一次，几分钱 | 1 到 3 秒 | 出本机：想法的标题与正文 | 每条只分一次，总量可控；轻量档足够分出三类 |
| 日总结（F10） | 中档对话模型 | 一天一次，几分钱 | 5 到 15 秒 | 出本机：当天的事项名、时长、随手记、问过 AI 的对话摘要 | 要一段能对外讲的话，轻量档写不出人话 |
| 面板对话（F4 执行中提问） | 中档对话模型 | 按次，几分钱 | 3 到 10 秒 | 出本机：当前这一步的名称与说明、用户这一句 | 只在执行中触发，频次最低，但要求答得准 |

默认档位统一为"中档对话模型"，用户可在设置里换成自己有的任何一家的兼容接口。没有 key 时这四项一律不启动：拆解与归类直接不做，日总结降级为随手记的机械整合，面板对话的输入框只读。

**隐私这一列不能空着**。它决定阶段 6 那句"什么数据发了出去"怎么写：发出去的只有上表右四列写的那几样，API key 经系统加密存在本机（不入库、不打日志），数据库文件不上传、不同步。

### 提示词版本记录

每改一次都记一笔，不然改坏了不知道回退到哪一版。

| 版本 | 改了什么 | 为什么改 | 通过率变化 |
| --- | --- | --- | --- |
| v1 | `planSystemPrompt` + `planUserPrompt`：只许回 `{"reply":"", "steps":[{"name":"","task":""}]}`，3 到 5 步、步名 6 字内动词开头、事项 15 字内且能立刻动手、回话 30 字内，不输出工期与优先级 | 拆解要的是结构稳定，先钉死形状，解析才敢只做容错不做猜测 | 首版，未统计 |
| v1 | `askSystemPrompt`：一句话 120 字内、不堆称呼与感叹号、不知道就说不知道 | 面板气泡位置小，回一段废话等于没回 | 首版，未统计 |
| v1 | `classifySystemPrompt` + `classifyUserPrompt`：只回类名本身、2 到 6 字、归不出就回「无法归类」，类名要短到能进左栏那一列 | 归类结果直接落库当分类名，回一句解释就会顶掉分类表 | 首版，未统计 |
| v1 | `summarySystemPrompt` + `summaryUserPrompt`：一段 80 到 150 字、不分条不加标题不用 Markdown、只用给到的材料、不评价好坏不猜动机 | 这张卡只有一种字号，井号与列表符号是噪音；PRD 明写不评价用户「效率高低」 | 首版，未统计 |
| v1.1 | 归类与日总结各加一句硬约束（归类「只输出类名本身」、日总结「不分条、不用 Markdown、不评价」） | 失败样例 1–4 全是模型自由发挥出来的格式问题，解析层已兜一半，提示词里堵另一半 | 待实机跑满 20 条后回填 |

### 固定用例集 + 通过率下限

- **用例集**：20 条写死在 [AI能力验收表.md](AI能力验收表.md)，归类 10 条、日总结 10 条，每条带输入、期望与判定标准。拆解与问一问的 22 条在同一个文件的能力清单里。
- **通过率下限**：拆解 75%、问一问 80%、归类 80%、日总结 80%。定完不许为了过关而调低，达不到就改提示词或换模型。
- **失败样例**：已留 4 条（类名写成整句、把「无法归类」当类名、日总结带 Markdown、总结里给「有点低效」的评价），处理方式都是改清洗或改提示词。

> **本版通过率下限**：归类 80%、日总结 80%
> **用例集位置**：[AI能力验收表.md](AI能力验收表.md)
> **本版实际通过率**：未跑（链路层 23 条自动化已过；真实模型那 20 条要读安全存储里的 key，测试进程解不开，只能在应用里点，表里两栏留白待填）

## 技术选型

选型依据见 [adr/0002-flutter-windows-first.md](adr/0002-flutter-windows-first.md)，这里只列清单与取舍。版本号不写死，建工程时取当时可用的稳定版。

| 包 | 用途 | 为什么是它 | 备选 |
| --- | --- | --- | --- |
| flutter（Windows 桌面） | 一套代码覆盖桌面与后续的移动端 | 常驻场景下体积与内存优于 Electron；自绘控件让界面不随系统版本漂移 | Electron、WinUI 原生 |
| flutter_riverpod | 状态管理与依赖注入 | "当前事务"要跨面板、列表、记录共享，提到一个 Provider 里最省 | Bloc、Provider |
| go_router | 路由与地址直达 | 桌面没有地址栏，但"气泡点查看直接落到我的项目"要靠地址表达；官方维护，比手写 Navigator 2.0 少一层样板 | 手写 RouterDelegate、auto_route |
| drift + sqlite3_flutter_libs | SQLite 数据层，类型安全 | 记录页的按月聚合、进度查询都靠 SQL，不靠遍历 | Hive、Isar、JSON 文件 |
| window_manager | 无边框、置顶、尺寸与位置 | 桌宠窗口的基础能力 | bitsdojo_window |
| screen_retriever | 屏幕工作区 | 贴边与吸附要算扣掉任务栏之后的可见区，自己读显示器信息在不同缩放比下不可靠 | 自算 DPI、读注册表 |
| tray_manager | 托盘图标与菜单 | 常驻形态的退出与找回入口 | system_tray |
| launch_at_startup | 开机自启 | PRD 的"开机自己出现" | 手动写注册表项 |
| win32 + ffi | 存 API key | key 不进数据库、不进日志；`flutter_secure_storage` 的 Windows 实现要编译器带 ATL，本机 `atlstr.h` 找不到、构建过不去，改成直接调 DPAPI 自己加密落盘 | 写成插件调用 |
| http 或 dio | AI 请求 | 只需要 POST 一个接口，标准库就够 | dio |
| file_picker | 挑图片与文件 | 桌面要弹系统文件框，Windows 与后续桌面平台共用一套；返回字节，不必自己拼 `OPENFILENAME` | 自写 win32 对话框、file_selector |
| intl | 日期与时长格式 | 记录页与流水的时间显示 | 自己格式化 |

不引入的：状态管理再套一层（如同时用 Bloc 与 Riverpod）、UI 组件库（界面按方向 A 自绘，引入组件库反而要把它的默认样式全改掉）。

## 类设计

开发的先后顺序见 [开发任务拆解.md](开发任务拆解.md)：24 个任务块，每块只覆盖一处原型，全部执行完即覆盖八页与 F1 到 F12。

### 分层

依赖方向自上而下，`domain` 不依赖任何一层，也不 import Flutter——PRD 第 198 行要求给移动端预留空间，这一层是换平台时唯一不用改的部分。

```text
app/        壳、路由、主题、ProviderScope 与依赖注入
features/   按八页切：pet、panel、tasks、records、projects、ideas、settings
domain/     实体与用例，纯 Dart
data/       drift 数据库、DAO、Repository 实现、migration
platform/   窗口、托盘、自启、安全存储、通知（Windows 实现都在这里，换平台只换这层）
ai/         客户端、提示词、结构化解析、降级
```

### 领域模型

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| `Project` | id、name、desc、dueAt、currentStep、createdAt | 项目容器，组织方式固定为流程顺序 |
| `Step` | id、projectId、index、name、state | 流程中的一步；删步时其下事项转为未分配 |
| `TaskItem` | id、scope（solo/project）、projectId?、stepId?、name、desc、spentSec、done、doneAt、source、aiUsedAt、orderIndex | 独立事项与项目待办合一，卡片、计时、随手记完全一致，只差归属；`orderIndex` 只在同一步内比较，跨步按步骤 `index` 排（它不具全局意义） |
| `Note` | id、ownerType（task/history/dayThought/daySummary）、ownerId、body、updatedAt | 随手记与记录页文字共用一张表：`task`/`history` 是随手记；`dayThought` 是第 5 页的「我的感想」，`daySummary` 是每条事项 AI 总结里用户改过的那版，两者的 `ownerId` 都是 `日期\|组键\|条目`（今日小结写 `日期\|summary\|summary`） |
| `TimeLog` | id、taskId、startedAt、endedAt、seconds | 一次执行的流水，停止即写一条，不填字段 |
| `DailyRecord` | id、date、summaryText、summaryEditedAt | 按天一条；`summaryEditedAt` 有值表示用户改过，AI 不再覆盖 |
| `Idea` | id、title、body、categoryId?、classifiedAt?、createdAt | 想法；`classifiedAt` 为空才会送 AI 归类。它有两个来源：AI 归上了，或用户在下拉里亲手选了分类（手动选的说了算，AI 不再覆盖） |
| `Category` | id、name、color | 只由 AI 生成，用户可改名；想法存 categoryId，改名不牵连想法 |
| `ChatMessage` | id、ownerType（panel/project）、ownerId、role、text、at | 执行中的对话，按事务隔离 |
| `ProgressEntry` | id、projectId、stepIndex、text、at、revisionCount | 进度史一条；第 6 页的"改过 N 次"由 revisionCount 出 |
| `Revision` | id、targetType、targetId、before、after、at | 改动留痕，日总结与进度史可改但都留这册子 |
| `Settings` | keyConfigured、demoUrl、repoUrl、bubbleEnabled、side、anchorY | key 只存"配没配"，值在系统安全存储里 |

### 用例

| 用例 | 做什么 | 对应功能 |
| --- | --- | --- |
| `StartTask` | 标记为当前、开始走秒；同时只能有一条在跑 | F4 |
| `StopTask` | 结算时长写 `TimeLog`，累计回 `TaskItem` | F4、F6 |
| `ClassifyIdea` | 标题与正文送 AI，落到某个分类；已分过的不再送 | F8 |
| `SummarizeDay` | 当天的事项、时长、随手记与问过 AI 的对话 → 一段总结；无 key 降级为随手记的机械整合 | F10 |
| `FinishTask` | 勾上完成：写进度史一条，随手记跟到进度史；退回未完成：只翻状态，已写下的那条史不动 | F4、F7 |

### 服务

| 服务 | 承担什么 |
| --- | --- |
| `PetWindowController` | 无边框、置顶、贴边吸附、左键拖拽、展开收起 |
| `TrayController` | 托盘图标、菜单、退出入口 |
| `AutoStartController` | 开机自启开关 |
| `TimerService` | 走秒、暂停、停止；停止才写库，不做每秒落盘。带累计基线起表（`baseMs`）时不重复累加库里已有的秒数 |
| `ChatClient`（`ai/chat_client.dart`） | OpenAI 兼容的 `/chat/completions`，默认 DeepSeek（`deepseek-chat`），超时 30 秒。结果只三种：`ChatReply` 拿到、`ChatNoKey` 没配 key、`ChatError` 这次没成（并带一句能直接上屏的话）。无 key 不算错，不抛异常。没附件时 `content` 仍是纯字符串（老模型照旧），带了附件才换成数组：文字一段、图片一段 `image_url`（`data:` + base64）、文本文件正文并进文字段并标出文件名 |
| `ProjectPlanner`（`ai/ai_project_planner.dart`） | 项目拆解：项目名与目标 → 步骤与事项。`PlanReady` / `PlanNotConfigured` / `PlanFailed` 三态，失败给回话，不把异常抛给界面。带附件时目标可以为空，话术里写「按附件判断」 |
| `AttachmentPicker`（`platform/files/desktop_attachment_picker.dart`） | 系统文件对话框挑图片与文本：一张图 ≤ 4MB、一份文本 ≤ 8000 字、一次 ≤ 5 个；认不出的后缀与被跳过的文件不整批作废，能用的先收下，原因交给界面补一句灰字 |
| `PlanParser`（`ai/plan_parser.dart`） | 拆解结果的结构化解析：剥 ```json 围栏与前后废话，最多 8 步（提示词只让给 3 到 5 步，多出来的当噪音），步名截 20 字、事项名截 40 字、回话截 120 字，没有步名的那条丢弃 |
| `ProjectPlanWriter` | 拆解结果落库：空流程时替换占位步骤 1，已有内容时追加到末尾；返回写进库的步骤数 |
| `IdeaClassifier` / `DaySummarizer` | 归类与日总结各一个端口：`AiIdeaClassifier` 把回话收拾成一个能落库的类名（去引号、去「分类：」前缀、截 12 字，说「无法归类」就返回 null），`AiDaySummarizer` 把 `DayDigest` 摊成材料换一段 150–200 字的正文（去 Markdown、超长截断）；没 key 或没答成都返回 null，前者让想法留在未分类，后者让日总结降级成随手记整合 |
| `SecureKeyGateway` | key 的读写与清除。端口不说怎么存，Windows 实现是 DPAPI 加密落盘；换平台只换 `platform/` 那份 |

## 语义修订：2026-10-25 实机反馈 12 条

使用者回填 B16 手动测试表后提的 12 条，改的是既有语义，记在这里当作后续源码的准绳（原型 `prototype/整体原型.html` 没写的以本节为准）。

| 项 | 原来的说法 | 现在的说法 |
| --- | --- | --- |
| 桌宠尺寸 | 收起 20%、展开 30% 短边 | 收起 15%、展开 25%（各降 5 个百分点） |
| 小任务窗口尺寸 | 宽 30%、高 40% | 宽 25%、高 35%（各降 5 个百分点） |
| 桌宠贴哪 | 收起贴桌面边缘，展开坐进主界面右／左下角 | 三档都贴**桌面右缘**（2026-10-26 起只做右缘，左缘暂不做）；主界面仍是七成居中，窗口取「主界面 ∪ 宠物」 |
| 展开态能不能拖 | 不能，一按下就收起 | 能拖：按住竖直拖，松手只记住高度、侧别恒为右缘 |
| 主界面能不能拖 | 不能，只能点五个标签 | 也不能：2026-10-27 起主界面固定居中，顶部那 16 像素只当留白，没有可抓的地方。只有桌宠能拖——常驻档交给系统整窗跟手，主界面档由窗口层铺满工作区、宠物自己跟手，主界面钉在原地 |
| 计时「暂停」 | 停表，按「继续」再走 | 同样只停表：不结算、不标完成，独立事项页那一格勾选框转黄 |
| 停止 | 清成 0，只给「开始」 | 停表 + 结算 + 标完成 + 面板回无事项；重置连流水一起清 |
| 独立事项编辑页随手记 | 失焦自动保存 | 只在点「保存」时落盘（小任务窗口那一格仍是失焦即存） |
| 「今天建的」 | 只有今天／昨天／N 天前 | 刚刚 / N 分钟前 / N 小时前 / 昨天 / 前天 / N 天前 |
| 「累计」 | 最少 1 分钟 | 精确到秒：没计过写「累计 0 秒」 |
| 面板布局 | 随手记 → 问一问 → 回答 → 动作区，整块可滚 | 标题/流程轴 → 随手记 → 计时行（紧贴随手记）→ 回答区（占满剩余）→ 问一问（钉最底），整块不滚 |
| 空态文案 | 「当前无正在进行的事务」+「点桌宠进主界面挑一件」；「还没有独立的事」+ 蓝色新建键 | 「当前无正在进行的事项」一句话；「还没有独立事项」一句话（新建入口只留页头那一个） |
