# 开发任务拆解

这份把 Flutter 开发工作切成 24 个带顺序的小块。全部执行完，八页原型与 F1 到 F12 就都落地了；每块只做自己那一份，执行一次即算完，后面的块只调用不返工。

技术路线见 [adr/0002-flutter-windows-first.md](adr/0002-flutter-windows-first.md)，类设计见 [07-开发.md](07-开发.md) 的「类设计」一节。这份只管"按什么顺序做、每块做到什么算完"。

## 拆解规则

1. **一块只覆盖一处原型**。以 `prototype/整体原型.html` 的页面为单位切块；跨页的公共能力（窗口、托盘、计时、AI 客户端）各自单独成块，且只成一块。
2. **目录互斥**。每块只准碰自己那一层：窗口只在 `platform/window`，托盘与自启只在 `platform/tray` 与 `platform/autostart`，计时只在 `TimerService`，AI 只在 `ai/`。块间不留"顺手改一下"的缝。
3. **前置未完不开工**。每块列出前置块，依赖图无环。
4. **完成判定写死**。每块给出可观察的通过条件，不写"基本完成"。
5. **禁止返工**。后面的块要用前面块的能力，只能调用，不能改。
6. **测试不过不算完**。每块的完成 = 功能实现 + 本块测试全过 + 编号更小的所有块测试重跑全过，三样都满足才标记完成；结果按下面的规矩留档。

### B10 计时服务与计时条

- **前置**：B09
- **覆盖**：第 2 页的计时；第 4、6 页的「开始」复用同一份服务
- **产出**：`TimerService`（`platform/timer/`）：走秒、暂停/继续、停止，注入 `now` 便于测；每秒 tick 只刷界面不落库；同一时刻只允许一条在跑（`StartTask(runningTaskId:)` 挡一层，服务自己再挡一层）；停止即调既有 `StopTask` 写一条 `TimeLog` 并把秒数累加到 `TaskItem.spentSec`；面板内按钮原位换成计时条
- **完成判定**：走秒每秒刷新但库里 `TimeLog` 与 `spentSec` 在停止前不变；停止后流水与累计各多一条；暂停期间不涨、继续后不丢；收面板与 Esc 不停表
- **校准（2026-10-24，对照整体原型第 2 页 `renderAction` 1302–1350 与 `.timerbar` 202–210）**：
  - 计时条数值定死：时钟 21px / 行高 1 / 字距 .5 / tabular-nums，暂停转 `--ink2`；`space-between` + `gap:10` + 上边距 12；按钮 44×min38、圆角 10、白底、边 `--line`；停止键 `#d94a3d` 白字；暂停图标 15、停止 14
  - 时间格式照原型 `fmt`：`mm:ss`，分钟不封顶；原型 `slice(-2)` 在超过 99 分钟会截断，那是写法漏洞，不照搬
  - 停止时 `startedAt` 传 `now - 净毫秒`：`StopTask` 用 `endedAt - startedAt` 算秒数，这样暂停那段不会混进去，不必改用例
  - 跑着点「标记完成」：原型只清计时没记流水（1345 行），是漏写；本块补成先结算再完成
  - 图标改用 Material 的 `pause_rounded` / `play_arrow_rounded` / `stop_rounded`，原型是内联 SVG，形状一致
  - 按钮悬停照原型 `.timerbar button:hover{border-color;color}` 与 `.stop:hover{background:#c8402f}`：只换颜色不挪位置；首版以「弹层里再 hover 易误触」砍掉，二轮校准补回
  - 与 PRD 对不上两处：PRD「点标记完成后面板收起」和同页状态表、原型都冲突，按停在完成态办；PRD「两件的秒数各算各的」按「时长分账、切走不停表」理解，不推翻「同一时刻只一条」
  - **顺延**：第 4 页列表行内的时钟与「开始」、第 6 页待办行的时钟归 B12、B15；「标记完成 600 毫秒后从列表移出」是列表动画，归 B12；面板里的「开始」不收起主界面（原型只有第 4、6 页的 `soloStart`/`pjStart` 会 `main.classList.remove('on')`）

## 测试与留档

### 形态

能自动化的用 Dart 测试跑：列表、表单、记录页、想法盒这些界面写 `flutter test` 的 widget 测试。窗口、托盘、开机自启这类必须手动的，写成点击清单由人执行。两种都算"测试脚本"，结果一视同仁地逐行留档。

### 什么时候跑

- **本块做完**：写本块的测试脚本，跑完，结果写进本块的结果文件
- **本块完成前**：把编号更小的所有块的测试脚本全部重跑一遍，结果追加进本块结果文件，并在总记录里记一行

也就是说，完成 B12 时要跑 B12 的测试，再跑 B01 到 B11 的全部测试。编号越大，重跑面越大——这是故意的，越晚的块越不能悄悄弄坏早期的功能。

### 文件与命名

```text
docs/测试结果/
├── 总记录.md                # 每次跑的时间、任务块、跑了哪些块、通过几条失败几条
├── B06-窗口层.md            # 每块一个，文件名与任务块同名
├── B09-悬停小面板.md
└── ...
```

每块结果文件里，一行一个测试结果，只写这一行的结论，操作与期望写在脚本里：

```text
2026-11-02 B09 首跑
点击常驻态桌宠，成功弹出悬停小面板
切到形态 B 的事务，面板标题跟着换成该事务名
在随手记输入一段文字后切走，再切回来文字还在
按 Esc，面板收起且计时未停
```

失败也要写，并且写清是哪一条、失败长什么样。只写通过的档不算数。

### 总记录的格式

| 时间 | 任务块 | 跑了哪些块 | 通过 | 失败 | 失败明细 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

失败明细指向对应块结果文件里的那一行，不在这里展开。

### 通过标准

- 本块结果文件里没有失败行
- 重跑的编号更小的块结果文件里也没有新增失败行
- 两条都满足，这一块才算完成，才能开下一块
