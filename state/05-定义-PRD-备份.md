## 二、背景与目标

### 2.1 背景

**宏观**：ADHD 在中文互联网上正从医学议题变成自我认同标签，成年人群体的确诊与自我识别在增加。现有工具都在解决"该做什么"和"专注多久"，几乎没有人做"怎么开始"。详见 [03-市场分析](03-市场分析.md)。

**微观**：我自己就是目标用户。想做的事和该做的事都停在计划里，开不了头；开了头也容易半途而废；做完的事转头想不起来。这三件事每天都在发生。

产品定位、四类「不做什么」、失败预判，见 [01-立项与边界](01-立项与边界.md)。

### 2.2 目标

**v1 要上线什么**：一个桌面常驻的助手，能在你需要开始的那一刻出现在你面前，把下一步拆到不用下决心的程度，并在你停手之后自动记录。

**用什么衡量**：「本来不会开始，但开始了」的次数。

| 项 | 内容 |
| --- | --- |
| 怎么记 | 产品自己判断。我在某件事上点了"开始"，就记一次 |
| 为什么这么记 | 不让我额外操作。事后勾选、弹窗确认这类做法都会变成新负担 |
| 它的代价 | 点"开始"不等于真的开始 |

**这个代价要记住**：所以这个数字只能当趋势看。阶段 08 要用真实使用记录校准它，别把它当结论。

**达到什么就算成功**：连续使用了足够多次之后，我不再需要特意想起它，它已经在我开始做事之前出现过。

## 三、故事介绍

### 3.1 用户场景

三类痛点，场景卡见 [02-用户调研](02-用户调研.md)。

| 痛点 | 一句话 |
| --- | --- |
| 启动不了 | 想动，但起不来；或者动了会愧疚 |
| 决策内耗 | 在几件事之间纠结，推演后果推不出结果，焦虑到转去刷视频 |
| 留不住东西 | 想法滞留在 AI 对话记录里；做完的事想不起来 |

### 3.2 价值分析

见 [03-市场分析](03-市场分析.md) 的结论：作为生意不值得，作为个人项目值得。价值在真实可用、作品价值、以及启动层这个真空位。

### 3.3 核心体验路径

```
出现 → 给一步 → 许可 → 拆解 → 记录 → 梳理
```

五条核心流程，每条写清触发条件、助手做什么、我做什么、什么时候算结束。

#### 流程 1 · 启动

| 项 | 内容 |
| --- | --- |
| 触发条件 | 我打开电脑，或助手从后台恢复；也可以是我把鼠标推到屏幕边缘或点右下角主动唤出 |
| 助手做什么 | 只显示一件事：当前项目的「下一步」。不铺列表，不显示"你今天还有 N 件事"，不显示任何未完成计数 |
| 我做什么 | 看一眼，决定做还是不做 |
| 结束条件 | 我开始动手，或明确说"不做"。说"不做"也算结束，不算失败 |

**对应场景**：启动不了 · 起不来、不想动。

#### 流程 2 · 规划

| 项 | 内容 |
| --- | --- |
| 触发条件 | 给出的「下一步」需要我从两件以上都值得做的事里选，例如求职与配音都有可推进的下一步 |
| 助手做什么 | 把后果摆出来：每个选择会失去什么。如果焦虑来自"还有更重要的事"，给出时间分配（两边都分到）。如果焦虑化解不了，不推这件事，转去处理焦虑本身 |
| 我做什么 | 看完后果，选一个；或者接受时间分配；或者说不选 |
| 结束条件 | 选定一个，或明确"今天不选"。今天不选也是合法结束 |

**硬约束**：时间分配必须基于真实的截止时间与已有投入记录，不能凭空给。

#### 流程 3 · 执行

| 项 | 内容 |
| --- | --- |
| 触发条件 | 我选定了某件事 |
| 助手做什么 | 把这件事拆到"不用下决心"的下一步。拆解要快；拆不出来或等太久时，退到一个不依赖 AI 的兜底动作（例如"先做五分钟"）。执行期间不弹窗、不提醒、不打断 |
| 我做什么 | 做。中途可以停，停了不扣分 |
| 结束条件 | 我停下，不管做了多少 |

**硬约束**：必须有不等 AI 的兜底路径，否则 AI 一慢整条链路就断。

#### 流程 4 · 记录

| 项 | 内容 |
| --- | --- |
| 触发条件 | 我停下之后自动触发 |
| 助手做什么 | 记一条流水：做了什么、多久、在哪个项目上。不需要我确认、不需要我填任何字段。记错了就改正，并留一条修订日志 |
| 我做什么 | 什么都不做；发现记错了才说一声 |
| 结束条件 | 流水写入即结束；若有修订，修订日志同步更新 |

#### 流程 5 · 回顾

| 项 | 内容 |
| --- | --- |
| 触发条件 | 每天结束时自动运行；也可以是我主动点开日历里的某一天 |
| 助手做什么 | 每日梳理：把当天流水整理成"今天做了什么"。把与项目相关的部分写进该项目的进度史，每条带时间戳。梳理错了就编辑原条目，并留一条修订日志 |
| 我做什么 | 不看也可以；发现了再改 |
| 结束条件 | 梳理写入进度史；若有修订，修订日志同步更新 |

**两条记录流程的共同规则**：记录可以改正，改正必须留痕。修订日志记两样：改了什么、什么时候改的。

### 3.4 指标预测

只用已经定过的那个指标，不编新数字。

| 环节 | 预计 | 理由 |
| --- | --- | --- |
| 助手出现 | 每天都会出现 | 它自己启动，不依赖我想起 |
| 点开始 | 每周若干次 | 从"每天偶尔"到"经常"都算正常，不设目标值 |
| 真正做完 | 低于点开始的次数 | 点开始不等于真的开始，这是已知代价 |

**不给具体比例的原因**：没有同类产品的数据可参照，编一个数字只会让阶段 08 校准的时候多一个要解释的偏差。

### 3.5 路径规划

**v1 做**：功能矩阵里的 9 条功能加 1 条基础结构。

**v1 之后**：见 [v2 候选清单](v2候选清单.md)。目前有六条：关键词搜索、从零新增气泡、手机端、账号与多用户、投递类工具、边缘停靠加强。

### 3.6 纸上预演

用纯文字把 MVP 的实际链路走一遍，看会不会卡死。

| 步骤 | 我做什么 | 助手做什么 | 卡在哪 |
| --- | --- | --- | --- |
| 1 出现 | 坐下打开电脑 | 已经在桌面边缘，不遮挡 | 一出现就铺一堆待办，变成愧疚制造机 |
| 2 给一步 | 看一眼 | 只显示「现在最小的一步」 | 要我从列表里挑，选择就又回到我头上 |
| 3 许可 | 犹豫该不该做这个 | 说这段时间归这件事，并给出两边的时间分配 | 分配是编的，看一眼就不信了 |
| 4 拆解 | 说"行" | 把事拆到不用下决心的程度 | 拆解要等 AI 算，慢了就不想等 |
| 5 记录 | 做完 | 自动记一条流水，不需要我确认 | 要我自己填或者点头，就不会做 |
| 6 梳理 | 不看 | 晚上自动梳理，写进项目进度史 | 梳理错了要我改，又变成负担 |

**要点**：预演的目的是找走不通的地方，不是确认它能走通。走完一处没卡，说明走得不够细。

**六个卡点的用途**：它们不是功能清单，是第五章页面设计的输入。其中两条直接约束界面形态：助手不能一出现就铺一堆待办，不能让我从列表里挑。

## 四、概要设计

### 4.1 模块设计

| 模块 | 包含什么 | 为什么单独成模块 |
| --- | --- | --- |
| M1 桌宠本体 | 常驻形态、唤出、收起与展开姿态、气泡承载 | 它是所有功能的入口，也是产品形态本身 |
| M2 项目与事务 | 项目容器、事务、下一步拆解 | 基础结构 F7 的落地处 |
| M3 决策辅助 | 后果对比、许可与时间分配、冲突检测 | 服务决策内耗这一类 |
| M4 记录与梳理 | 流水、每日梳理、项目进度史、修订日志、可讲述段落 | 服务留不住东西这一类 |
| M5 进度与日历 | 投入量计算、日历格子、主进度条、最长连续 | 服务启动不了里的每日维持 |
| M6 提醒与气泡 | 三档气泡、截止提示、气泡参数设置 | 全产品唯一会主动打扰的部分，单独隔离便于约束 |
| M7 设置与偏好 | 唤出快捷键、梳理排序偏好、气泡开关 | 个性化配置 |

### 4.2 功能清单

| 编号 | 模块 | 功能 | 追到的场景 |
| --- | --- | --- | --- |
| F1 | M1 | 助手自己出现，不需要我去打开它 | 启动不了 · 起不来 |
| F2 | M2 | 把当前的事拆到"不用下决心"的下一步 | 启动不了 · 起不来 |
| F3 | M3 | 许可三段式 | 启动不了 · 动了会愧疚 |
| F4 | M3 | 把后果摆出来，列清每个选择会失去什么 | 决策内耗 |
| F5 | M4 | 从对话记录里自动接住想法 | 留不住东西 · 方向一 |
| F6 | M4 | 每日梳理 → 项目进度史 → 可讲述段落 | 留不住东西 · 方向二 |
| F8 | M5 | 主进度条 + 日历 + 最长连续 | 配音练习需要每天做一点才有效 |
| F9 | M6 | 截止提示，只给截止时间与不做的后果 | 没注意到笔试截止 |
| F10 | M3 | 冲突检测，两件事时间上撞了提前指出 | 兼职试岗与笔试冲突 |
| F7 | M2 | 项目制容器（基础结构，不计入功能清单） | 无对应场景，但它是 F4/F6/F8 的共同前提 |

**编号说明**：F7 空缺在功能清单里，但它必须实现。它答不上"对应哪条场景"，所以不占功能名额。

**规则**：有功能追不到场景就砍掉。不要改场景去迁就功能。

#### F3 许可三段式

1. 先摆出做这件事的好处，回答"我为什么值得花这个时间"
2. 如果焦虑来自"还有更重要的事"，给出时间分配，两边都分到
3. 如果焦虑化解不了，不推这件事，转去处理焦虑本身

第 3 步是这条功能的分界线。它把"要不要做"的决定权留给我。

### 4.3 页面结构

七个页面，关系如下：

```
桌面常驻态 ①
   │ 唤出
   ▼
主面板 ② ──┬── 选择对比 ③（两件事都值得做时）
            ├── 执行中 ④
            └── 项目详情 ⑥ ── 日历 ⑤
                                  
设置 ⑦（从任一页面进入）
```

| # | 页面 | 对应流程 | 模块 |
| --- | --- | --- | --- |
| 1 | 桌面常驻态 | 启动 | M1 |
| 2 | 主面板 | 启动 | M1 |
| 3 | 选择对比 | 规划 | M3 |
| 4 | 执行中 | 执行 | M2 |
| 5 | 日历 | 回顾 | M5 |
| 6 | 项目详情 | 回顾 | M4 |
| 7 | 设置 | — | M7 |

### 4.4 MVP 范围与不做清单

**v1 只解决一件事：让"本来不会开始"的事真的开始。**

项目容器、拆解、许可、后果、记录、截止提示、冲突检测都只服务于这一件事；与"开始"无关的一律不做。

| 不做 | 理由 |
| --- | --- |
| 手机端 | 它的场景是坐在电脑前 |
| 账号 / 多用户 | 只有一个用户 |
| 简历按 JD 定制投递、招聘网站自动筛选与投递 | 属于求职项目内部，不是助手本身的功能 |
| 社交 / 排行榜 / 分享 | 会引入我不想面对的横向比较 |
| 全功能项目管理工具 | 越俎代庖。正确做法是提示我去用专业工具 |
| 替我做决定 | 会削弱我自己判断的能力，和 F3 第 3 步是同一件事的两面 |
| 语音交互、主题皮肤等装饰 | 与"让事情开始"无关 |
| 多设备同步 | 单机够用，而且它会牵出账号体系 |
| 定时提醒轰炸 | 只做带后果的截止提示 |

## 五、详细设计（页面原型）

七个页面，每页六段：什么时候出现、屏幕上有哪些元素、大致布局、能做的操作、状态变化、不要做什么。

**这份文档只描述要画什么，具体版面由我用 Axure 画。**

### 第 1 页 · 桌面常驻态

**什么时候出现**：开机自启动后一直在，不需要我做任何事。

**屏幕上有哪些元素**

- 桌宠本体（人形或精灵造型）
- 收起状态：只露出半张脸和一只手，扶在屏幕边缘
- 展开状态：全身
- 悬停时可能出现的一个小气泡（见第 2 页）

**大致布局**：贴在屏幕左侧边缘中部，垂直于桌面视觉重心附近，不压在工作区中央。具体位置可拖拽并记住。

**能做的操作**

- 悬停：本体从收起到半展开
- 点击：打开主面板（第 2 页）
- 拖拽：移动位置，松手后记住
- 右键：打开设置（第 7 页）

**状态变化**

| 状态 | 表现 |
| --- | --- |
| 正常 | 收起姿态，有轻微呼吸或眨眼 |
| 悬停 | 半展开，露出眼睛 |
| 有未读气泡 | 头顶一个小圆点，不显示文字 |
| 全屏应用时 | 自动隐藏或降到最低层级（待定，见 06 的技术约束） |

**不要做什么**

- 不要挡住任何窗口的操作区域
- 不要抢焦点，除非光标进入它的范围
- 不要在任务栏占位
- 不要常亮动画。动效要慢、要小，余光扫不到时就该看不到

### 第 2 页 · 主面板

**什么时候出现**：点击桌宠本体后打开。

**屏幕上有哪些元素**

- 一个窄面板，附着在桌宠旁边
- 顶部：当前项目名
- 中间：一句话，就是「现在的下一步」
- 底部：一个主按钮，文字是"开始"
- 右下角：一个不显眼的"换一个"

**大致布局**：竖长条，宽度约 280 像素，高度随内容。贴着桌宠那一侧展开，不居中、不遮住当前窗口的标题栏。

**能做的操作**

- 点"开始"：进入执行中（第 4 页）
- 点"换一个"：在同一项目里换下一个待办，不跳出项目
- 点项目名：进入项目详情（第 6 页）
- 按 Esc：收起，回到桌面常驻态
- 直接说"不做"：收起，记为一次主动跳过

**状态变化**

| 状态 | 表现 |
| --- | --- |
| 有下一步 | 显示那一句话加"开始"按钮 |
| 没有下一步 | 显示"这个项目暂时没有下一步"，并给一个"现在想一件"的入口 |
| 多个项目都值得做 | 不显示列表，改为进入选择对比（第 3 页） |
| 加载中 | 显示上一句话，不显示转圈 |

**不要做什么**

- **不显示未完成计数**。"你还有 12 件没做"是愧疚制造机
- **不给列表**。一给列表，选择就又回到我头上
- 不显示进度条
- 不显示项目切换器

### 第 3 页 · 选择对比

**什么时候出现**：两件以上都值得做的事同时可推进时，从主面板自动进入。

**屏幕上有哪些元素**

- 每个选项一块卡片，横向并排，最多三块
- 每块卡片上：项目名、这件事是什么、**做它会失去什么**、预计花的时间
- 底部：一行提示"不选也可以"

**大致布局**：居中浮层，宽度约 640 像素。卡片等宽，从左到右按"哪个更紧急"排。

**能做的操作**

- 点卡片任意位置：选定它，进入执行中（第 4 页）
- 点"不选"：关闭浮层，记为一次主动跳过
- 按 Esc：同上

**状态变化**

| 状态 | 表现 |
| --- | --- |
| 两项 | 两块卡片各占一半 |
| 三项 | 三块等分 |
| 超过三项 | 只展示最紧急的三项，其余折叠成"还有几件"（点开才展开） |
| 某一项缺截止时间 | 卡片上如实写"没有截止时间" |

**不要做什么**

- **不给"我替你决定"的选项**。没有"你帮我选"这个按钮，决定权必须在我
- 不用红色标注"紧急"，那会制造新的压力
- 不显示"你上次选的是这个"

### 第 4 页 · 执行中

**什么时候出现**：在第 2 页或第 3 页选定之后。

**屏幕上有哪些元素**

- 一句话：现在要做的这一个动作
- 一个"停了"按钮
- 一句小字：可以随时停

**大致布局**：和主面板同一个位置、同一宽度，内容替换。视觉上极简，只有文字和一个按钮。

**能做的操作**

- 点"停了"：结束，进入记录（自动，无界面）
- 按 Esc：同上
- 说"拆小一点"：换一个更小的动作

**状态变化**

| 状态 | 表现 |
| --- | --- |
| 刚开始 | 显示拆解出来的第一个动作 |
| 拆解失败或超时 | 显示兜底动作"先做五分钟"，不显示错误信息 |
| 停了 | 面板收起，无任何结算动画 |

**不要做什么**

- **不要进度条**
- **不要倒计时**
- **不要"还剩多少"**
- 不要计时结束后弹窗表扬或催促

**理由**：这三样都会让"停"变成有代价的事，而流程 3 的设计前提是"停了不扣分"。

### 第 5 页 · 日历

**什么时候出现**：从项目详情进入，或从设置里的入口进入。

**屏幕上有哪些元素**

- 月历网格，每个格子的背景是当天各项目的投入分布
- 格子右上角：与项目有关的完成件数
- 格子左上角：与项目无关的完成件数
- 顶部：月份切换
- 底部：图例（哪个颜色对应哪个项目）

**大致布局**：整屏或大浮层。月历占主要面积，图例在底部一行。

**能做的操作**

- 点某一天：展开当天的记录（浮层或侧栏）
- 左右切换月份
- 点图例上的项目：只高亮那一个项目

**状态变化**

| 状态 | 表现 |
| --- | --- |
| 有投入 | 按投入量比例分区，每个项目至少占 20% |
| 超过五个项目 | 只画投入量最大的四个，其余合并成一条灰色"其他" |
| 只有非项目事务 | 背景为中性灰，左上角有数字，右上角无数字 |
| 完全没做事 | 背景留白，不填充任何颜色 |

**不要做什么**

- **不要用红色表示"没做"**。空白就是空白，不是失败
- 不要显示"连续未打卡多少天"
- 不要在格子上写评价性文字

### 第 6 页 · 项目详情

**什么时候出现**：从主面板点项目名进入，或从日历点某天再点进项目。

**屏幕上有哪些元素**

- 顶部：项目名、主进度条、最长连续
- 中部：进度史，按梳理的组织方式排列
- 下部：时间轴视图的切换入口
- 右上角：一个"讲给我听"按钮，生成可讲述段落

**大致布局**：全屏页面。顶部固定在视野内，中部可滚动。

**能做的操作**

- 切换组织方式：流程顺序 / 由浅入深 / 按类型分组（这是项目级设置，改一次就记住）
- 切换到时间轴视图
- 点某条记录：展开看它的修订日志
- 点"讲给我听"：生成一段能直接拿去讲的文字

**状态变化**

| 状态 | 表现 |
| --- | --- |
| 有进度史 | 按组织方式排列，每条带时间戳 |
| 还没有进度史 | 显示"这个项目还没有梳理过"，给一个手动触发的入口 |
| 某条被改过 | 该条旁边有一个小标记，点开看修订链 |

**不要做什么**

- **不要默认展示全部流水**。默认给的是梳理过的进度史，流水要点开才有
- 不要在进度史里显示"你今天没做"

### 第 7 页 · 设置

**什么时候出现**：右键桌宠，或从任一页面的入口进入。

**屏幕上有哪些元素**

- 唤出快捷键
- 梳理排序偏好（按项目设置）
- 气泡开关与时机（每条默认气泡一行）
- 数据位置与导出

**大致布局**：常规设置页，左侧分类，右侧表单。

**能做的操作**

- 改快捷键
- 对每条气泡调整：什么时候出现（唤起时／待机时自动）、要不要跳转、开不开
- 导出数据

**状态变化**

| 状态 | 表现 |
| --- | --- |
| 快捷键冲突 | 立即提示，并建议一个可用组合 |
| 全部气泡关闭 | 允许，但要提示"截止提示也会一起关闭" |

**不要做什么**

- 不提供"从零新增一条气泡"（属于 v2）
- 不提供账号、同步、主题等与 v1 无关的入口

## 六、交付设计

### 6.1 数据要看什么

个人产品没有数据分析师，埋点只服务一个问题：**我下次还会不会打开它**。

| 要看的 | 为什么 |
| --- | --- |
| 每天出现的次数与实际点开的次数 | 出现多而点开少，说明它出现了但没说服我 |
| 点开始到停下的时长分布 | 判断"拆解"是不是拆得够小 |
| 主动跳过的次数 | 跳过不等于失败，但连续跳过多说明推荐错了 |
| 记录被修订的次数 | 修订太多说明梳理质量差 |
| 气泡被无视的次数 | 判断气泡有没有变成噪音 |

报表形态：一张周视图，五行并排。不做好看的仪表盘。

### 6.2 上线筹备

见 [09-发布](09-发布.md)。个人产品没有其他团队，需要协调的只有一件事：它会不会和已有的输入法、录屏、会议软件抢快捷键。
